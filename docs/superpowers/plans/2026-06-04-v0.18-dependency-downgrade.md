# v0.18 哥斯拉依赖类降级 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 伪装包名但仅被加载、未注册成组件的依赖类（class-* 型，如哥斯拉注入的 Jackson 库）从 critical 降到 high；critical 只留激活的真注册马。

**Architecture:** 改 `MasqueradedPackageRule`——伪装包名 +5 仅对非 class-* 型 finding 生效；class-* 型返回 0。依赖类少 +5 → 14→9 = high；真马（tomcat-/spring-）不变。单文件规则改动 + 集成测试。

**Tech Stack:** Java 8（agent 模块），JUnit 5，Maven（`./mvnw.cmd`）。

参考 spec：`docs/superpowers/specs/2026-06-04-v0.18-dependency-class-downgrade-design.md`

**关键既有事实（已确认）：**
- `MasqueradedPackageRule.evaluate` 现为：`if (finding==null||className==null||ctx==null||ctx.whitelist==null) return 0; if (!ctx.whitelist.isFrameworkPackage(className)) return 0; if (codeSource==null||isEmpty()) return 5; return 0;`
- `MasqueradedPackageRuleTest` 的 `finding(className, codeSource)` helper **不设 type**（默认 null）——现有期望 +5 的用例 type=null 非 class-*，本改动后仍 +5，不回退。
- `RuleEngineTest` 已有 v0.13 集成测试（`godzilla_masqueraded_filter_scored_critical` 用 tomcat-filter）。
- mapLevel：score≥10 critical，≥7 high，≥4 suspicious。
- `Finding.type`(String)、`score`(int)、`className`、`codeSource`、`attributes`(Map 默认非 null)。
- 受信前缀含 `org.apache.coyote.`（DefaultWhitelist），`ctx.whitelist.isFrameworkPackage` 命中。

- [ ] **Step 3: 改实现**

`MasqueradedPackageRule.evaluate` 在 `if (codeSource null/empty)` 块内、`return 5;` 之前加 class-* 门：
```java
    @Override
    public int evaluate(Finding finding, ScanContext ctx) {
        if (finding == null || finding.className == null || ctx == null || ctx.whitelist == null) return 0;
        if (!ctx.whitelist.isFrameworkPackage(finding.className)) return 0;
        if (finding.codeSource == null || finding.codeSource.isEmpty()) {
            // v0.18: the masquerade bonus only applies to registered components (tomcat-/spring-).
            // A class-* finding is a merely-loaded class, not an activated memshell — most likely a
            // dependency library the real shell pulled in (Godzilla ships Jackson renamed into
            // org.apache.coyote.* and defines those classes alongside the registered filter shells).
            // Such a class is still reported, but must not be elevated to critical.
            if (finding.type != null && finding.type.startsWith("class-")) return 0;
            return 5;
        }
        return 0;
    }
```
（同时更新类 Javadoc 末尾的「Known limitation」段不是必须，但可加一句 v0.18 行为说明；非强制。）

```markdown
### v0.18：哥斯拉依赖类降级（已完成）

v0.17 去重暴露 critical 层混着「非内存马」：哥斯拉为让 Filter 马运行而一起注入的 Jackson 库类
（伪装成 org.apache.coyote.*、class-* 型、未注册成组件、无访问路径）被 masqueraded-package +5
顶到 critical，与真马同级，使 critical 数虚高（实地 critical 8 中 4 个是依赖类）。

- 改 `MasqueradedPackageRule`：伪装包名 +5 **仅对注册组件（tomcat-/spring-）生效**；
  class-* 型（ClassScanner 全类视角、仅被加载的类）返回 0
- 依赖类少 +5（14→9）落到 high——仍报、不漏，但不与激活的真马同级 critical
- 真注册马（tomcat-filter，有 isDynamic + urlPatterns）仍 +5、仍 critical（v0.13 行为不回退）
- 语义：只有被容器注册、能拦请求的伪装类才是激活的内存马；仅被加载的伪装类是马的依赖库
- 哥斯拉原理：Filter 马靠 Jackson 反序列化收发，整个 Jackson 改包名打包进 payload 一起注入；
  注册的是 Filter（客户端 getAllFilter 可见），Jackson 工具类只是依赖库
- 实地（哥斯拉 ground truth）：critical 8→4（只剩 4 个真注册 Filter 马，与客户端 getAllFilter
  一致），4 个依赖类降 high；JSP shell、哥斯拉 Servlet 马不受影响
- 参考：`docs/superpowers/specs/2026-06-04-v0.18-dependency-class-downgrade-design.md`
```
