# JavaMemHunter v0.2 — 容器与 Spring 运行时扫描设计

## 1. 概要

| 项 | 内容 |
|---|---|
| 版本 | v0.2 |
| 主线 | Tomcat 容器内部对象扫描 + Spring HandlerMapping/Interceptor 扫描 + runtime-only 单条评分规则 |
| 不在范围 | 字节码扫描、白名单、基线对比、清理操作、HTML/Markdown 报告、WebFlux |
| 前置工作 | v0.1 实施完成（已交付）|
| 后续依赖 | v0.4 基线 + 完整规则引擎；v0.5 清理 |

## 2. 目标与非目标

### 2.1 目标

1. 定位目标 JVM 中所有 Tomcat `StandardContext`，枚举其 Filter / Servlet / Listener / Valve。
2. 定位 Spring `ApplicationContext`，枚举 `HandlerMapping` 中的 `HandlerMethod` 与 `HandlerInterceptor`。
3. 引入 `runtime-only` 评分规则：对象存在于运行时注册表但无法在已知声明来源中找到声明 → 标 `suspicious`。
4. 修复 v0.1 评审遗留的 4 个 Important 项（原子写入、BFS 防环、未知选项告警、Listener 子类型细分）。
5. 端到端验证：通过 `test-target-injector` 注入模拟内存马，扫描报告应正确标记 `runtime-only`。

### 2.2 非目标

- 不做 Tomcat 以外容器（Jetty / Undertow / WebLogic）。
- 不做 Spring WebFlux。
- 不做白名单或基线对比（推迟 v0.4）。
- 不做字节码读取与关键字匹配（推迟 v0.4）。
- 不做清理操作（推迟 v0.5）。
- 不引入完整 17 条评分规则，仅做 1 条 runtime-only。

### 3.2 关键设计决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| Tomcat Context 定位 | MBean 优先 + 类遍历兜底 | MBean 兼容 Tomcat 7-10，95% 场景覆盖；类遍历兜底处理禁用 JMX |
| Spring Context 定位 | DispatcherServlet 优先 + ServletContext attribute 兜底 | 覆盖 Spring MVC + Spring Boot 2/3；不支持 WebFlux |
| 跨版本反射 | 单一扫描器 + `ReflectUtil` 字段名候选 fallback | 内部对象差异本质是字段名/类型微调，不需要整套 Strategy 模式 |
| 评分规则 | 仅 runtime-only 一条 | 单条做对、做准比堆砌 6 条粗糙规则有用 |
| runtime-only 判定 | 注解 + Spring Bean + web.xml 三链兜底 | 不依赖基线即可实时判定；接受小概率误报 |

## 4. 数据流

### 4.1 agentmain 扫描流程

```text
1. AgentArgs.parse(rawArgs)
   └─ 未知选项 → System.err 警告（不中断）

2. 元信息采集
   └─ scanId, pid, javaVersion, os, timestamp

3. ClassScanner.scan() → List<Finding> type="class-*"

4. TomcatScanner.scan()
   ├─ providerChain.findAllContexts()
   │   ├─ MBeanContextProvider 试
   │   ├─ 失败 → ClassLoadedContextProvider 试
   │   └─ 全失败 → 返回 []，partialErrors += "tomcat context not found"
   └─ 对每个 StandardContext：
       ├─ TomcatFilterScanner → type="tomcat-filter"
       ├─ TomcatServletScanner → type="tomcat-servlet"
       ├─ TomcatListenerScanner → type="tomcat-listener-request|context|session"
       └─ TomcatValveScanner → type="tomcat-valve"

5. SpringScanner.scan()
   ├─ providerChain.findAllApplicationContexts()
   │   ├─ DispatcherServletProvider 试
   │   ├─ 失败 → ServletContextAttrProvider 试
   │   └─ 全失败 → []
   └─ 对每个 ApplicationContext：
       ├─ SpringMappingScanner → type="spring-mapping"
       └─ SpringInterceptorScanner → type="spring-interceptor"

6. RuntimeOnlyDetector.evaluate(finding) — 对 Tomcat/Spring findings
   ├─ 三链判定：
   │   ├─ Class 上有 @WebFilter / @WebServlet / @WebListener？
   │   ├─ Class 在 Spring BeanDefinition 列表中？
   │   └─ 名称出现在 ServletContext web.xml 标准注册位置？
   ├─ 任一命中 → 维持 level="low", score=3
   └─ 全部 miss → reasons += "runtime-only", level="suspicious", score+=3

7. Summary 统计 + JsonReportWriter.write() 原子写入
```

### 4.2 数据模型变化

#### Finding（修改）

#### Finding ID

v0.1：`finding-<type>-sha256(type|className|"")`

v0.2 容器对象：`finding-<type>-sha256(type|className|nameDiscriminator)`，其中 `nameDiscriminator`：

| 类型 | discriminator |
|---|---|
| `class-*` | `""`（保持 v0.1 行为） |
| `tomcat-filter` | filterName |
| `tomcat-servlet` | servletName |
| `tomcat-listener-*` | listenerObject identityHashCode 十六进制 |
| `tomcat-valve` | container path + pipelineIndex |
| `spring-mapping` | pattern + methods |
| `spring-interceptor` | interceptorClass identityHashCode 十六进制 |

效果：同一 className 注册成多个 FilterDef 时 ID 不同；同一对象跨次扫描 ID 稳定。

## 5. 组件设计

### 5.1 ReflectUtil

```java
public final class ReflectUtil {
    // 读单个字段，可达 → Optional.of；不可达 → Optional.empty
    public static Optional<Object> tryReadField(Object target, String fieldName);

    // 按候选字段名依次尝试，第一个成功的返回
    public static Optional<Object> tryReadAnyOf(Object target, String... fieldNames);

    // 遍历类继承链查字段（处理 private 字段在父类的情况）
    public static Optional<Field> findFieldInHierarchy(Class<?> clazz, String fieldName);

    // 安全调用无参方法
    public static Optional<Object> tryInvoke(Object target, String methodName);
}
```

所有方法：
- 不抛 checked exception，内部 catch
- 失败返回 Optional.empty
- 自动 `setAccessible(true)`
- 不缓存 Field（v0.2 扫描频率低，无性能压力）

### 5.2 Tomcat 扫描器

#### StandardContextProvider

```java
public interface StandardContextProvider {
    /** 返回所有可定位的 StandardContext。失败返回空列表，不抛异常。 */
    List<Object> findAllContexts(Instrumentation inst);
}
```

实现：
- `MBeanContextProvider`：通过 `ManagementFactory.getPlatformMBeanServer()` 查询 `Catalina:type=Context,*`，反射拿 MBean 关联的真实 StandardContext 对象
- `ClassLoadedContextProvider`：在 `inst.getAllLoadedClasses()` 中找 `StandardEngine` / `StandardHost` 实例（通过反射读取静态字段或扫描所有实例），递归 `getChildren()` 找到所有 Context

`TomcatScanner` 依次尝试 Provider，第一个返回非空就用。

#### TomcatFilterScanner

读取字段（按 fallback 顺序）：

| 字段 | 候选名 | 类型 |
|---|---|---|
| FilterDef 字典 | `filterDefs` | `Map<String, FilterDef>` 或 `Hashtable` |
| FilterMap 数组 | `filterMaps` | `FilterMap[]` 或 wrapper 类内的 `array` 字段 |
| FilterConfig 字典 | `filterConfigs` | `Map<String, ApplicationFilterConfig>` |

输出 Finding 字段：
- `name` = filterName
- `className` = filterClass
- `attributes`：urlPatterns, dispatcherTypes, filterClass, contextPath, fromConfigFile (boolean，best-effort)

#### TomcatServletScanner

通过 `StandardContext.findChildren()`（公开方法，先 try 这个）拿到所有 Wrapper，对每个 Wrapper：
- servletName = wrapper.getName()
- servletClass = wrapper.getServletClass()
- mappings = wrapper.findMappings() 或反射读 `mappings`

#### TomcatListenerScanner

读取 StandardContext 内两个字段，合并为单一 listener 列表：
- `applicationEventListeners`（Object[]）
- `applicationLifecycleListeners`（Object[]）

对每个 listener 实例，通过接口名字符串检测确定子类型（不依赖目标 JVM 的 servlet API 类加载）：

| 实现接口 | type 输出 |
|---|---|
| `javax.servlet.ServletRequestListener` 或 `jakarta.servlet.ServletRequestListener` | `tomcat-listener-request` |
| `javax.servlet.http.HttpSessionListener` 或 `jakarta.servlet.http.HttpSessionListener` | `tomcat-listener-session` |
| `javax.servlet.ServletContextListener` 或 `jakarta.servlet.ServletContextListener` | `tomcat-listener-context` |
| 都不匹配 | `tomcat-listener-other` |

子类型检测复用 `WebComponentDetector` 的接口名匹配逻辑，避免重复实现。同一对象同时实现多种 listener 接口时，按上表优先级输出一条 Finding（取首个匹配）。

注：Finding type 字符串使用连字符格式（`tomcat-listener-request`），与 `class-listenerrequest`（无连字符，受 lowercase 自动生成限制）有意保持区分——前者是容器层面发现，后者是类层面发现。

#### TomcatValveScanner

```java
Object pipeline = ReflectUtil.tryInvoke(context, "getPipeline");
Object valve = ReflectUtil.tryInvoke(pipeline, "getFirst");
while (valve != null) {
    findings.add(buildFinding(valve, "tomcat-valve"));
    valve = ReflectUtil.tryInvoke(valve, "getNext").orElse(null);
}
```

### 5.3 Spring 扫描器

#### ApplicationContextProvider

```java
public interface ApplicationContextProvider {
    List<Object> findAllApplicationContexts(Instrumentation inst);
}
```

`DispatcherServletProvider`：
- 在 `inst.getAllLoadedClasses()` 中找 `org.springframework.web.servlet.DispatcherServlet` 类的实例
- 难点：没法直接拿"所有实例"，但 DispatcherServlet 通常是 Tomcat Wrapper 持有的，所以这个 Provider 实际依赖 Tomcat Servlet 扫描的结果
- 实现细节：v0.2 简化为"从 TomcatScanner 已找到的 Servlet 列表中过滤出 DispatcherServlet 类实例，反射读取其 `webApplicationContext` 字段"

`ServletContextAttrProvider`：
- 从已定位的 ServletContext（Tomcat 那边拿）读 `org.springframework.web.context.WebApplicationContext.ROOT` attribute

#### SpringMappingScanner

```java
ApplicationContext ctx = ...;
Map<String, AbstractHandlerMethodMapping> beans =
    ReflectUtil.tryInvoke(ctx, "getBeansOfType", AbstractHandlerMethodMapping.class)
               .orElse(emptyMap());
for (mapping : beans.values()) {
    Map<RequestMappingInfo, HandlerMethod> handlers =
        ReflectUtil.tryInvoke(mapping, "getHandlerMethods").orElse(emptyMap());
    for (entry : handlers.entrySet()) {
        findings.add(buildFinding(entry, "spring-mapping"));
    }
}
```

Finding 字段：
- `name` = beanName + "#" + handlerMethod
- `className` = handlerMethod.getBeanType().getName()
- `attributes`：pattern, methods, handlerMethod, beanName

#### SpringInterceptorScanner

反射读 `AbstractHandlerMapping.adaptedInterceptors` 字段（`List<HandlerInterceptor>`），对每个 interceptor 输出 Finding。

### 5.4 RuntimeOnlyDetector

```java
public class RuntimeOnlyDetector {
    private final Object applicationContext;  // 可为 null
    private final Object servletContext;       // 可为 null

    /** 评估单个 finding，原地修改 reasons/level/score */
    public void evaluate(Finding finding);
}
```

三链判定：

```text
isRuntimeOnly(finding) =
   not (
      hasWebAnnotation(finding.className)
      OR isSpringManaged(finding.className)
      OR isInWebXml(finding.name)
   )
```

实现细节：

**hasWebAnnotation**：
- 尝试 `Class.forName(finding.className)`，读取 annotations
- 检查 `javax.servlet.annotation.WebFilter` / `WebServlet` / `WebListener`
- 同时检查 jakarta 版本
- 类不可达 → false

**isSpringManaged**：
- `ApplicationContext.getBeanNamesForType(Class.forName(className))` 不为空 → true
- ApplicationContext 不可达 → 跳过此项

**isInWebXml**：
- 反射读 ServletContext 的 web.xml 内部表示
- Tomcat 中是 `StandardContext.findFilterDef(name)` / `findChild(name)`
- 找不到 → false

任一为 true → 不标 runtime-only。三个都 false → 标。

### 5.5 升级现有组件

#### WebComponentDetector（修改）

替换递归实现为 BFS + visited 集合：

```java
private static boolean implementsInterface(Class<?> clazz, String ifaceName) {
    Set<Class<?>> visited = new HashSet<>();
    Deque<Class<?>> queue = new ArrayDeque<>();
    queue.add(clazz);
    while (!queue.isEmpty()) {
        Class<?> c = queue.poll();
        if (!visited.add(c)) continue;
        if (c.getName().equals(ifaceName)) return true;
        for (Class<?> i : c.getInterfaces()) queue.add(i);
        if (c.getSuperclass() != null) queue.add(c.getSuperclass());
    }
    return false;
}
```

shortName 升级：Listener 三类细分

```java
private static String shortName(String ifaceName) {
    if (ifaceName.endsWith(".Filter")) return "Filter";
    if (ifaceName.endsWith(".Servlet")) return "Servlet";
    if (ifaceName.endsWith(".ServletRequestListener")) return "ListenerRequest";
    if (ifaceName.endsWith(".ServletContextListener")) return "ListenerContext";
    if (ifaceName.endsWith(".HttpSessionListener")) return "ListenerSession";
    if (ifaceName.endsWith(".Valve")) return "Valve";
    if (ifaceName.endsWith(".HandlerInterceptor")) return "Interceptor";
    return ifaceName;
}
```

ClassScanner 中 type 字符串相应变化：`class-listenerrequest` 等。

#### AgentArgs（修改）

`parse` 维护一个已知选项集合：`{"output"}`。遇到未知选项打 `System.err.println("[memhunter] warning: unknown option --xxx")`，但不中断。

#### JsonReportWriter（修改）

```java
public void write(ScanReport report, String filePath) throws IOException {
    File finalFile = new File(filePath);
    File tempFile = new File(filePath + ".tmp");
    // ... mkdirs ...
    mapper.writeValue(tempFile, report);
    if (!tempFile.renameTo(finalFile)) {
        // Windows 上 renameTo 不能覆盖已存在文件，删后再 rename
        if (finalFile.exists() && !finalFile.delete()) {
            throw new IOException("Cannot delete existing report: " + finalFile);
        }
        if (!tempFile.renameTo(finalFile)) {
            throw new IOException("Atomic rename failed: " + tempFile + " -> " + finalFile);
        }
    }
}
```

## 6. 错误处理

- 每个 Provider 和 Scanner 内部 try-catch 顶层 Throwable
- 局部失败 → `ScanReport.partialErrors` 追加一项 `{scanner: "TomcatFilterScanner", reason: "field filterDefs not accessible"}`
- 字段反射失败 → Finding 的对应 attribute 缺失，不影响 Finding 整体生成
- agentmain 顶层仍保持 `catch (Throwable)` 兜底

## 9. 风险与已知限制

| 风险 | 影响 | 缓解 |
|---|---|---|
| `MBeanContextProvider` 在 JMX 禁用环境失败 | 标准场景 < 5% 概率 | 类遍历兜底 |
| Tomcat 字段名跨版本变化超出 fallback 列表 | 局部字段缺失，Finding 仍生成 | partialErrors 记录，v0.5 清理时扩展 fallback |
| Spring WebFlux 应用没有 DispatcherServlet | 完全无法扫描 | v0.2 显式不支持 |
| runtime-only 误报：编程式注册的正常 Filter | 噪声增加 | v0.4 白名单兜底；user 可在报告中手动忽略 |
| runtime-only 漏报：恶意逻辑嵌入正常 Bean | 严重漏报场景 | v0.4 字节码扫描覆盖 |

## 10. 实施约束

- 每个新文件 < 150 行
- 修改文件 < 50 行新增（如超出，先 review 边界）
- 所有反射字段读取走 `ReflectUtil`，不硬编码 `Field.setAccessible(true)`
- 局部 try-catch 必须将原因写入 `partialErrors`，不能静默吞掉
- 端到端报告必须归档至 `docs/superpowers/specs/v0.2-sample-report.json`

## 11. 与 v0.1 的差异

| 项 | v0.1 | v0.2 |
|---|---|---|
| 扫描范围 | JVM 已加载类 | 类 + Tomcat 容器 + Spring 运行时 |
| Finding 类型 | `class-filter`/`class-servlet`/`class-listener`/`class-valve`/`class-interceptor` | 增加 `tomcat-*` 和 `spring-*` 系列 |
| 评分规则 | codeSource 为空 → suspicious | 加 runtime-only 一条 |
| Listener 细分 | 统一 `class-listener` | 三子类型 `listenerrequest/listenercontext/listenersession` |
| 报告原子性 | 直接 writeValue | 临时文件 + rename |
| 选项校验 | 未知选项静默丢值 | stderr 警告 |
| 反射循环防护 | 递归无 visited | BFS + visited |
| 局部失败可见性 | 静默 | partialErrors 字段 |

## 12. 后续 v0.3+ 衔接

- v0.2 的 `RuntimeOnlyDetector` 三链判定将在 v0.4 升级为带白名单的多规则评分
- `Finding.attributes` 字段格式为 v0.4 规则引擎提供输入（如读取 `urlPatterns` 判定是否 `/*`）
- `ScanReport.partialErrors` 在 v0.4 升级为带分级的诊断字段
- v0.2 不引入字节码扫描，但 `ClassScanner` 已为 v0.4 两阶段扫描提供初筛输入
