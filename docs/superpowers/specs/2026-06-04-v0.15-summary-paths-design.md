# v0.15 设计：扫描摘要逐条追加访问路径/定位信息

**日期**：2026-06-04
**前置版本**：v0.14（attach 端扫描摘要 + 默认输出路径）
**背景**：v0.14 的终端摘要每条只显示 `[level] type className score=N`，**没有内存马的访问路径**。
而访问路径是应急人员最需要的信息——封 WAF、查访问日志溯源都靠它。路径信息其实已存在
finding 的 `attributes` 里（Filter 的 urlPatterns、Servlet 的 mappings、Spring 的 pattern、
冰蝎 Agent 型的 injectedStrings 等），只是没在终端摘要打印。

---

## 1. 目标 & 非目标

### 1.1 目标

terminal 摘要每条 critical/high/suspicious 末尾追加路径/定位信息：
- **有 URL 访问路径的类型**（filter/servlet/spring-mapping/spring-interceptor/agent-bytecode-tampered）→
  显示 `path=[...]`（可封堵/可溯源的路径）
- **无 URL 路径、靠事件/管道/类加载触发的类型**（listener/valve/transformer）→
  显示对应**定位字段**（`trigger=`/`pipeline=`/`class=`），明确告知"无可封路径、靠 XX 触发"
- 既无路径也无定位字段的（agent-dynamic-class）→ 不追加任何段

### 1.2 非目标

- 不改 scanner（路径/定位字段都已存在 attributes）
- 不改 agent、不改 JSON 报告（仍全量含所有 attributes，取证用）
- 不碰 clean/verify

---

## 2. 架构

纯 attach 端，扩展 v0.14 的 `ScanSummaryPrinter`。逐条打印 finding 时，按 `type` 从 attributes
取对应字段，格式化成一段追加到行尾。**有字段才追加，无则该行不变。**

### 2.1 类型 → 显示映射（printer 内查找）

| finding type | attributes 键 | 显示段 | 字段形态 |
|---|---|---|---|
| `tomcat-filter` | `urlPatterns` | `path=[...]` | List |
| `tomcat-servlet` | `mappings` | `path=[...]` | List |
| `spring-mapping` | `pattern` | `path=<值>` | String |
| `spring-interceptor` | `includePatterns`（+`excludePatterns`）| `path=[...]`（有 exclude 再附 ` exclude=[...]`）| List 或其它（兼容取值）|
| `agent-bytecode-tampered` | `injectedStrings` | `path=[...]`（截断）| List |
| `tomcat-listener-request/session/context/other` | `listenerKind` | `trigger=<值>` | String |
| `tomcat-valve` | `pipelineIndex` | `pipeline=<值>` | int |
| `agent-transformer` | `transformerClass` | `class=<值>` | String |
| `agent-dynamic-class` | （无）| 不追加 | — |

**语义区分**：`path=` = 可封堵的访问路径；`trigger=`/`pipeline=`/`class=` = 无 URL 路径，靠
事件/管道/类加载触发——让用户明白不是"漏提取"。

### 2.2 值格式化

- **List 类型**（urlPatterns/mappings/injectedStrings/includePatterns 当其为数组时）：
  用 JsonNode 遍历元素拼成 `[a, b, c]`。
- **String/标量**（pattern/listenerKind/pipelineIndex/transformerClass）：直接 `asText()`。
- **includePatterns/excludePatterns 类型不定**（反射读字段，JSON 里可能是数组也可能是字符串）：
  isArray → 拼 `[...]`；否则 → asText() 原样。
- **injectedStrings 截断**：冰蝎注入字串可能几十条。只取前 5 条拼 `[a, b, c, d, e, ...(+N more)]`
  （N = 总数 - 5）；≤5 条则全显示、无省略。完整内容仍在 JSON。

### 2.3 健壮性

attributes 缺该键、键值为 null、类型与预期不符 → 不追加该段、不抛异常（JsonNode `.path()`
返回 MissingNode，`.isArray()` 为 false，`.asText("")` 返回空 → 视为无值跳过）。空 List → 不追加。

### 2.4 文件

- 修改：`attach/src/main/java/com/memhunter/attach/ScanSummaryPrinter.java`
  （逐条打印循环里追加路径/定位段；新增私有 helper `appendLocation(StringBuilder, JsonNode finding)`）
- 修改：`attach/src/test/java/com/memhunter/attach/ScanSummaryPrinterTest.java`

## 4. 测试 & 验收

### 4.1 单元测试（扩展 ScanSummaryPrinterTest）

构造含各类型 finding 的临时 JSON，断言每条行尾的路径/定位段：
- `tomcat-filter` + urlPatterns=["/*"] → 行含 `path=[/*]`
- `tomcat-servlet` + mappings=["/dsad/dsad"] → 行含 `path=[/dsad/dsad]`
- `spring-mapping` + pattern="/admin" → 行含 `path=` 和 `/admin`
- `spring-interceptor` + includePatterns=["/api/**"] + excludePatterns=["/api/login"] →
  行含 `path=[/api/**]` 和 `exclude=[/api/login]`
- `agent-bytecode-tampered` + injectedStrings 7 条 → 行含前 5 条 + `...(+2 more)`，不含第 6/7 条
- `agent-bytecode-tampered` + injectedStrings 3 条 → 全显示、无 `more`
- `tomcat-listener-request` → 行含 `trigger=request`
- `tomcat-valve` + pipelineIndex=2 → 行含 `pipeline=2`
- `agent-transformer` + transformerClass="com.x.T" → 行含 `class=com.x.T`
- `agent-dynamic-class` → 行**不含** `path=`/`trigger=`/`pipeline=`/`class=`
- finding 无对应 attributes 键（如 filter 但 urlPatterns 缺失）→ 不追加、不抛
- 既有 v0.14 测试（计数行、low 不列、降级）仍通过

### 4.2 验收（实地）

对哥斯拉靶机 scan（不带 --output），验证终端摘要：
- 哥斯拉 Filter 马行尾显示 `path=[/*]`
- 哥斯拉 Servlet 马（className=null）行尾显示 `path=[/dsad/dsad]` 等真实 mapping
- 若有 listener/valve 型，显示 `trigger=`/`pipeline=`
