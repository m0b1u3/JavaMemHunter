# v0.12 设计：误报治理

**日期**：2026-06-03
**前置版本**：v0.11（注入内容提取）
**背景**：真实靶场扫描暴露信噪比 ~1:125——252 个 finding 里真阳只有 2 个
（JSP shell + 冰蝎 redefine HttpServlet），其余 250 个噪音淹没了真实威胁，
工具实战不可用。

噪音构成（真实数据）：
- `agent-dynamic-class` **132 个**：几乎全是 `sun.reflect.GeneratedMethodAccessor*`
  / `$Proxy*` / `$$Lambda$*` 等 JVM 自身机制产生的类
- `tomcat-servlet` critical **19 个**：Tomcat examples 自带 Servlet
  （HelloWorldExample / async0~3 / CookieExample…）
- `tomcat-valve`/`tomcat-filter` high 若干：Tomcat 内置组件
- `class-*` 兜底重复约 45 个

---

## 1. 目标 & 非目标

### 1.1 核心哲学转变

从「**动态注册 = 可疑**」转向「**有恶意特征才可疑**」。真实应急场景没有干净基线
（到现场时木马已在里面），工具必须靠**内置知识**区分「正常业务组件」和「内存马」。

### 1.2 目标

把信噪比降到可用水平，**不漏任何已验证真阳**（JSP shell、冰蝎 Agent redefine）。

三个噪音源治理：
1. **DynamicClassScanner 132 个** → 内置 JVM 生成类白名单 + 要求字节码恶意特征才报
2. **RuntimeOnlyRule 的 servlet/filter/valve 误报** → 降权（+4→+1）+ 新增
   `BenignComponentRule` 负分（codeSource 正常 + 无恶意特征 → 压到 low）
3. JVM 生成类白名单与恶意特征判断抽公共 helper 复用

### 1.3 非目标

- 不依赖现场基线对比（明确排除——真实环境没有干净基线）
- 不引入 ML / 外部威胁情报
- 不改检测覆盖面：v0.10/v0.11 的检测能力（4 Tomcat + 2 Spring + 3 agent 型）不动，
  只调评分与过滤
- 不抑制 `agent-*` 型 finding（bytecode-tampered/transformer/dynamic-class 是确定性
  恶意证据，BenignComponentRule 跳过它们）

## 3. BytecodeMaliceCheck（公共 helper）

复用现有 `ScanContext.bytecodeOf(className) -> BytecodeAnalysis`，统一判断恶意特征。
`BytecodeAnalysis` 实际 API：`hasMethodCall(owner, namePattern)` /
`hasMethodCallByName(namePattern)` / `hasMethodCallByOwnerPrefix(prefix)`。

```java
package com.memhunter.agent.scoring;

import com.memhunter.agent.model.ScanContext;
import com.memhunter.agent.scoring.bytecode.BytecodeAnalysis;

/** Unified malicious-bytecode-feature check, shared by DynamicClassScanner and BenignComponentRule. */
public final class BytecodeMaliceCheck {

    private BytecodeMaliceCheck() {}

    /** True if the class's bytecode shows command-exec / dynamic-class-loading / reflection-abuse / crypto. */
    public static boolean hasMalice(String className, ScanContext ctx) {
        if (className == null || ctx == null) return false;
        BytecodeAnalysis a = ctx.bytecodeOf(className);
        if (a == null) return false;
        return a.hasMethodCall("java/lang/Runtime", "exec")
            || a.hasMethodCall("java/lang/ProcessBuilder", "start")
            || a.hasMethodCallByName("defineClass")
            || a.hasMethodCall("javax/crypto/Cipher", "doFinal")
            || a.hasMethodCallByName("getDeclaredMethod")   // 反射执行链典型起手
            || a.hasMethodCallByName("invoke");             // 反射调用
    }

    /** Overload for callers that have a Class<?> but no ScanContext bytecode cache (DynamicClassScanner). */
    public static boolean hasMalice(BytecodeAnalysis a) {
        if (a == null) return false;
        return a.hasMethodCall("java/lang/Runtime", "exec")
            || a.hasMethodCall("java/lang/ProcessBuilder", "start")
            || a.hasMethodCallByName("defineClass")
            || a.hasMethodCall("javax/crypto/Cipher", "doFinal")
            || a.hasMethodCallByName("getDeclaredMethod")
            || a.hasMethodCallByName("invoke");
    }
}
```

**注意**：`invoke` + `getDeclaredMethod` 单独看可能误判（很多正常类反射）。但
BytecodeMaliceCheck 是**和其他强信号组合使用**——在 BenignComponentRule 里它是
「不抑制」的条件之一，在 DynamicClassScanner 里它叠加在「codeSource=null + 非标准
loader」之上。实现时若实测发现 `invoke`/`getDeclaredMethod` 误报偏多，可在实现 task
里收紧为只保留 exec/ProcessBuilder/defineClass/Cipher 四个强信号——以实地扫描结果为准。

## 4. JvmGeneratedClasses（白名单）

```java
package com.memhunter.agent.scoring;

/** Recognises classes generated by the JVM's own mechanisms (reflection accessors, lambdas, proxies). */
public final class JvmGeneratedClasses {

    private JvmGeneratedClasses() {}

    private static final String[] PREFIXES = {
        "sun.reflect.GeneratedMethodAccessor",
        "sun.reflect.GeneratedConstructorAccessor",
        "sun.reflect.GeneratedSerializationConstructorAccessor",
        "jdk.internal.reflect.Generated",     // JDK 9+
        "com.sun.proxy.$Proxy",
        "sun.proxy.$Proxy"
    };

    public static boolean isJvmGenerated(String className) {
        if (className == null) return false;
        for (String p : PREFIXES) {
            if (className.startsWith(p)) return true;
        }
        if (className.contains("$$Lambda$")) return true;       // lambda synthetic
        if (className.matches("\\$Proxy\\d+")) return true;      // top-level dynamic proxy
        return false;
    }
}
```

## 5. DynamicClassScanner 降噪

`isSuspicious` 当前逻辑：`codeSource==null && (unusualLoader || shortName)`。加两层：

```java
boolean isSuspicious(Class<?> c) {
    if (c == null || c.getClassLoader() == null) return false;
    String name = c.getName();

    // v0.12: JVM 自身机制生成的类直接放行（132 噪音的主因）
    if (JvmGeneratedClasses.isJvmGenerated(name)) return false;

    // 原有：无 codeSource + (非标准 loader 或 短类名)
    java.security.ProtectionDomain pd = c.getProtectionDomain();
    if (pd == null) return false;
    java.security.CodeSource cs = pd.getCodeSource();
    boolean noSource = cs == null || cs.getLocation() == null;
    if (!noSource) return false;
    String loaderName = c.getClassLoader().getClass().getName();
    boolean unusualLoader = !STANDARD_LOADERS.contains(loaderName);
    boolean shortName = !name.contains(".") && name.length() <= 5;
    if (!(unusualLoader || shortName)) return false;

    // v0.12: 还要有字节码恶意特征才报（无特征的良性动态类不报）
    BytecodeAnalysis a = readBytecode(c);   // 见下
    return BytecodeMaliceCheck.hasMalice(a);
}
```

**字节码读取**：DynamicClassScanner 没有 ScanContext，需要自己读类字节码。用
现有 `ClassBytecodeReader.readAndAnalyze(className, classLoader)`（v0.4 已存在，
ScanContext.bytecodeOf 内部就调它）：

```java
private BytecodeAnalysis readBytecode(Class<?> c) {
    try {
        return ClassBytecodeReader.readAndAnalyze(c.getName(), c.getClassLoader());
    } catch (Throwable t) {
        return null;  // 读不到字节码 → 当作无恶意特征（不报，避免读失败误判）
    }
}
```

**注意**：读不到字节码时返回 null → hasMalice 返回 false → 不报。这偏保守
（可能漏报读不到字节码的动态类），但符合 v0.12「降误报优先」的目标，且
codeSource=null 的动态类绝大多数能读到内存字节码。

## 6. BenignComponentRule（业务组件抑制）

```java
package com.memhunter.agent.scoring.rules;

import com.memhunter.agent.model.Finding;
import com.memhunter.agent.model.ScanContext;
import com.memhunter.agent.scoring.BytecodeMaliceCheck;
import com.memhunter.agent.scoring.ScoringRule;

/**
 * Suppresses normal business components: a Servlet/Filter/Listener whose code comes from a
 * webapp's own jar/WEB-INF/classes and whose bytecode shows no malicious features is almost
 * certainly legitimate application code, not a memshell. Returns a large negative score to
 * push it down to "low". Agent-type findings (bytecode-tampered etc.) are NEVER suppressed.
 */
public class BenignComponentRule implements ScoringRule {

    public String name() { return "benign-component"; }

    public int evaluate(Finding finding, ScanContext ctx) {
        if (finding == null || finding.type == null || finding.className == null) return 0;
        // agent-* findings are deterministic malice evidence — never suppress
        if (finding.type.startsWith("agent-")) return 0;
        if (!isComponentFinding(finding.type)) return 0;

        if (!isNormalWebappCodeSource(finding.codeSource)) return 0;  // null/work-dir → not benign
        if (isHighEntropyName(finding.className)) return 0;            // random class name → not benign
        if (BytecodeMaliceCheck.hasMalice(finding.className, ctx)) return 0;  // malicious bytecode → not benign

        return -10;  // benign business component → push to low
    }

    private boolean isComponentFinding(String type) {
        return type.startsWith("tomcat-") || type.startsWith("spring-") || type.startsWith("class-");
    }

    private boolean isNormalWebappCodeSource(String cs) {
        if (cs == null || cs.isEmpty()) return false;
        if (cs.contains("/work/Catalina/")) return false;   // JSP-compiled temp dir = suspicious
        return cs.contains("/WEB-INF/") || cs.contains(".jar")
            || cs.contains("/classes/") || cs.contains("/webapps/");
    }

    // 简单高熵判定（复用 HighEntropyClassNameRule 思路；类名简单部分熵 > 阈值）
    private boolean isHighEntropyName(String className) {
        String simple = className;
        int dot = className.lastIndexOf('.');
        if (dot >= 0) simple = className.substring(dot + 1);
        return shannonEntropy(simple) > 3.5 && simple.length() >= 6;
    }

    private double shannonEntropy(String s) {
        if (s == null || s.isEmpty()) return 0.0;
        int[] freq = new int[128];
        int counted = 0;
        for (int i = 0; i < s.length(); i++) {
            char ch = s.charAt(i);
            if (ch < 128) { freq[ch]++; counted++; }
        }
        if (counted == 0) return 0.0;
        double ent = 0.0;
        for (int f : freq) if (f > 0) {
            double p = (double) f / counted;
            ent -= p * (Math.log(p) / Math.log(2));
        }
        return ent;
    }
}
```

**效果对照（真实扫描数据）：**

| finding | codeSource | 高熵? | 恶意字节码? | benign? | 结果 |
|---|---|---|---|---|---|
| HelloWorldExample | webapps/examples/.../classes/ | 否 | 否 | ✅ | -10 → low |
| async0~3 等 examples | webapp 目录 | 否 | 否 | ✅ | -10 → low |
| shell_jsp | /work/Catalina/.../ | — | — | ❌（work 目录） | 保持 high |
| 冰蝎 HttpServlet | agent-bytecode-tampered | — | — | ❌（agent- 跳过） | 保持 critical |
| 业务 Servlet 被植后门 | webapp jar | 否 | 是 | ❌（恶意字节码） | 保持高分 |

## 7. RuntimeOnlyRule 降权

```java
// 当前结尾：return 4;
// 改为：
return 1;   // v0.12: 动态注册降为弱信号；正常业务组件靠 BenignComponentRule 压低
```

其余逻辑（isDynamic=false 早返回、web 注解、Spring 托管早返回）不变。降到 +1 后，
单凭"动态注册"不足以让组件进 suspicious（阈值 4），需叠加其他信号。
