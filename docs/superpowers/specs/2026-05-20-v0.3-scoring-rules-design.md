# JavaMemHunter v0.3 — 评分规则引擎 + 白名单设计

## 1. 概要

| 项 | 内容 |
|---|---|
| 版本 | v0.3 |
| 主线 | Java 内置 + 文件覆盖白名单 + 12 条评分规则的规则引擎 + `--explain` 详细模式 |
| 不在范围 | 字节码扫描（v0.4）、基线对比（v0.4）、HTML/Markdown 报告、清理操作 |
| 前置完成 | v0.2 容器扫描已交付（feature/v0.2-container-scanning 分支已 merge 或可基于其上） |
| 后续依赖 | v0.4 字节码扫描将通过 `ScoringRule` 接口无缝接入 |

## 2. 目标与非目标

### 2.1 目标

1. 把当前粗糙的二元评分（v0.2: low/suspicious by `codeSource null` or `runtime-only`）升级为多维度规则引擎。
2. 内置 12 条评分规则，覆盖设计文档第 9 节中不依赖字节码的全部规则。
3. 内置 Java 白名单（包名前缀、CodeSource 路径、APM Agent 名），用户可通过 `--whitelist <file>` 追加。
4. CLI 新增 `--explain` 模式，报告中加入 `ruleHits` 字段展示每条命中规则与加分。
5. **核心验收**：v0.2 中 8 个 runtime-only 标记中的 5 个误报（WsFilter/StandardContextValve 等）降至 low；3 个真实注入（FakeFilter/Servlet/Interceptor）升至 high/critical。
6. 字节码规则接口预留：`ScoringRule` 接口，v0.4 直接实现新规则即可。

### 2.2 非目标

- 不做基线对比（v0.4）
- 不做字节码扫描（v0.4）
- 不做 YAML 规则配置（YAGNI，用纯文本白名单）
- 不做 `--disable-rule` 单规则禁用（避免扫描结果不可重现）
- 不做完整 17 条规则（5 条依赖字节码扫描，留 v0.4）

### 3.2 关键决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 评分形态 | `score=0` 起步 + 规则累计 | 规则表是评分唯一来源 |
| 等级阈值 | 0-3 low / 4-6 suspicious / 7-9 high / 10+ critical | 沿用设计文档第 9 节 |
| 规则架构 | `ScoringRule` 接口 + 每规则一个类 | 单元可测、扩展友好、字节码规则可无缝接入 |
| 白名单存储 | Java 内置常量 + `--whitelist <file>` 文本追加 | 零依赖、开箱即用、用户可覆盖 |
| CLI 暴露 | `--whitelist <file>`、`--explain` | 调试可观测，不暴露禁用规则避免结果不可重现 |
| RuntimeOnlyDetector 处理 | 删除，重写为 `RuntimeOnlyRule` | 命名范式统一为规则；旧 Detector 的"就地修改" 与新规则"返回 delta" 范式不一致 |

## 4. 数据流

### 4.1 agentmain 流程

```text
1. AgentArgs.parse(rawArgs)
   ├─ --output <file>
   ├─ --whitelist <file>   (新)
   └─ --explain            (新, 布尔)

2. Whitelist 加载
   ├─ DefaultWhitelist 内置（FRAMEWORK_PACKAGES / APM_AGENTS / CODESOURCE_PATHS）
   └─ 如有 --whitelist 文件 → 按行追加

3. 元信息采集 (scanId, pid, javaVersion, os, timestamp)

4. ClassScanner.scan() → List<Finding>
   - score=0, level=null, reasons=[], 不再写死分数
   - attributes 照常填充

5. TomcatScanner / SpringScanner 同上

6. ScanContext ctx = new ScanContext(appCtx, whitelist, explainFlag)

7. RuleEngine.evaluate(allFindings, ctx)
   对每个 finding:
   - for each rule:
       int delta = rule.evaluate(finding, ctx);
       if delta != 0:
         finding.score += delta
         finding.reasons.add(rule.name() + " (" + (+/-)delta + ")")
         if explain: finding.ruleHits.add(new RuleHit(rule.name(), delta))
   - finding.level = mapScoreToLevel(finding.score)
   - finding.recommendation = pickRecommendation(finding.level)

8. Summary 统计（按新等级分布）
9. JsonReportWriter.write()  原子写入
```

### 4.2 数据模型变化

#### Finding（修改）

```java
public class Finding {

    public String id, type, level, name, className, codeSource, classLoader, recommendation;
```

#### ScoringRule（接口）

```java
public interface ScoringRule {
    /** 规则唯一名，用于 reasons 和 ruleHits 输出 */
    String name();

    /**
     * 评估 finding。返回值即 score delta：
     * - 正数 → 风险信号，加分
     * - 负数 → 白名单/可信信号，减分
     * - 0 → 不命中，不影响分数
     *
     * 实现必须：
     * - 只读访问 finding（不修改任何字段）
     * - 不抛异常（内部 catch Throwable，failure → return 0）
     * - 容忍 finding.attributes 缺字段（不抛 NPE）
     */
    int evaluate(Finding finding, ScanContext ctx);
}
```

#### RuleEngine

```java
public class RuleEngine {
    private final List<ScoringRule> rules;

    public RuleEngine() {
        this(defaultRules());
    }

    /** Test seam */
    RuleEngine(List<ScoringRule> rules) {
        this.rules = rules;
    }

    private static List<ScoringRule> defaultRules() {
        return Arrays.asList(
            new ImplementsWebComponentRule(),
            new CodeSourceNullRule(),
            new CodeSourceTempDirRule(),
            new RuntimeOnlyRule(),
            new UrlPatternWildcardRule(),
            new FilterOrderAtTopRule(),
            new HighEntropyClassNameRule(),
            new NonBusinessPackageRule(),
            new UnusualClassLoaderRule(),
            new MappingPathDisguiseRule(),
            new WhitelistHitRule(),
            new ApmAgentRule()
        );
    }

    /** 对每个 finding 应用所有规则。Mutates findings in place. */
    public void evaluate(List<Finding> findings, ScanContext ctx) {
        for (Finding f : findings) {
            evaluateOne(f, ctx);
        }
    }

    private void evaluateOne(Finding f, ScanContext ctx) {
        if (ctx.explain) f.ruleHits = new ArrayList<>();
        for (ScoringRule rule : rules) {
            int delta;
            try {
                delta = rule.evaluate(f, ctx);
            } catch (Throwable t) {
                continue;  // never crash on a bad rule
            }
            if (delta == 0) continue;
            f.score += delta;
            String sign = delta > 0 ? "+" : "";
            f.reasons.add(rule.name() + " (" + sign + delta + ")");
            if (ctx.explain) f.ruleHits.add(new Finding.RuleHit(rule.name(), delta));
        }
        f.level = mapLevel(f.score);
        f.recommendation = recommend(f.level);
    }

    static String mapLevel(int score) {
        if (score >= 10) return "critical";
        if (score >= 7) return "high";
        if (score >= 4) return "suspicious";
        return "low";
    }

    private static String recommend(String level) {
        switch (level) {
            case "critical": return "Immediate review required: highly likely a memshell.";
            case "high":     return "Manual review strongly recommended.";
            case "suspicious": return "Review when convenient; cross-check with baseline.";
            default:         return "Informational only.";
        }
    }
}
```

### 4.3 12 条规则契约

| Rule name | 输入字段 | 命中条件 | Delta |
|---|---|---|---|
| `implements-web-component` | `finding.type` | type 以 `class-`、`tomcat-`、`spring-` 开头 | +3 |
| `code-source-null` | `finding.codeSource` | == null | +3 |
| `code-source-temp-dir` | `finding.codeSource` | 包含 `/tmp/`, `/var/tmp/`, `\AppData\Local\Temp` | +3 |
| `runtime-only` | `finding.className`, `ctx.applicationContext` | 既无 `@Web*` 注解，又不在 Spring Bean | +4 |
| `url-pattern-wildcard` | `attributes.urlPatterns` (List<String>) | 包含 `/*` 或 `/` | +2 |
| `filter-order-at-top` | `attributes.pipelineIndex` 或 `attributes.order` | 数值 ≤ 1 | +2 |
| `high-entropy-class-name` | `finding.className` | 简单名 Shannon 熵 > 3.5 | +1 |
| `non-business-package` | `finding.className`, `ctx.whitelist` | 既不属于 framework 也不属于 business 包 | +2 |
| `unusual-classloader` | `finding.classLoader`, `ctx.whitelist` | 类名不在常见 ClassLoader 列表 | +2 |
| `mapping-path-disguise` | `attributes.pattern` | 类似 `/health`、`/actuator/*`、`/static/*`、`/favicon.ico` 但 className 不属于框架包 | +2 |
| `whitelist-hit` | `finding.className`, `ctx.whitelist` | className 以白名单包名开头 | **-5** |
| `apm-agent` | `finding.className`, `ctx.whitelist` | className 包含 APM Agent 标识 | **-4** |

## 5. 错误处理

- `RuleEngine.evaluateOne` 对每条规则 `try { delta = rule.evaluate(...); } catch (Throwable) { continue; }`
- 任何规则抛异常 → 跳过该规则，其他规则继续，finding 不被破坏
- `Whitelist.loadFromFile` IOException → MemHunterAgent 在 agentmain 顶层 catch，记录到 `partialErrors`，仍然继续扫描（仅默认白名单生效）
- 所有反射/属性读取走 try-catch 返回安全默认值

## 8. 与 v0.2 的差异

| 项 | v0.2 | v0.3 |
|---|---|---|
| 评分来源 | Scanner 写死的 score=3 + RuntimeOnlyDetector +3 | RuleEngine 累计 12 条规则 |
| Level 计算 | low / suspicious 二元（score 3 vs 6） | low / suspicious / high / critical 四级 |
| 白名单 | 无 | Java 内置 + 用户文件追加 |
| Reasons | 单条 "registered in Tomcat" + 可能 "runtime-only" | 每条命中规则一行（带 delta） |
| ruleHits | 不存在 | --explain 模式输出 |
| CLI | --output | --output --whitelist --explain |
| RuntimeOnlyDetector | 独立类 | 删除，作为 RuntimeOnlyRule 之一 |

## 9. v0.4+ 衔接

- v0.4 字节码扫描将通过新增 ScoringRule 实现接入：
  - `BytecodeRuntimeExecRule`（Runtime.exec / ProcessBuilder）+4
  - `BytecodeDefineClassRule`（defineClass）+3
  - `BytecodeReflectionAbuseRule`（getDeclaredField + setAccessible）+2
  - `BytecodeCryptoRule`（Cipher / Base64）+2
  - `BaselineNewRule`（v0.4 基线对比）+4
- 这些只需要实现 `ScoringRule` 接口加入 `RuleEngine.defaultRules()` 列表即可，无需重构

## 10. 实施约束

- 每个新文件 < 100 行（除 RuleEngine 可到 150 行）
- 每条规则严格只读 Finding，不修改字段
- 所有规则必须 catch Throwable，failure → return 0
- 白名单文件解析容忍空行、注释（`#` 开头）、不识别的 type 跳过并 warn
