# v0.11 设计：被篡改类的注入内容提取

**日期**：2026-06-02
**前置版本**：v0.10.2（BytecodeTamperScanner 覆盖冰蝎 redefine 目标类）
**背景**：v0.10.2 在真实环境成功检出冰蝎 Agent 型内存马——
`agent-bytecode-tampered: javax.servlet.http.HttpServlet`，方法体 `service()` 被改，
memSize 15183 > diskSize 11111（多出 4072 字节 shellcode）。但当前 finding 只报告
"哪个类的哪个方法被改了"，**没有提取被注入的内容**。应急响应需要内存马的访问路径
（封堵 WAF、查访问日志溯源）、解密类名、payload 特征——这些都藏在被 redefine 的
方法体的字符串常量里。

---

## 1. 目标 & 非目标

### 1.1 目标

1. BytecodeTamperScanner 检出 `agent-bytecode-tampered` 后，提取内存字节码相对
   磁盘 JAR **新增的字符串常量**（含访问路径、解密类名、payload 特征字串）。
2. 启发式过滤出"可疑字串"子集，同时保留全量原始新增字串（不漏）。
3. 把被改类的**内存字节码 + 磁盘原始字节码** dump 到 `evidence/<finding-id>/` 存证，
   供事后人工反编译/对比。

### 1.2 非目标

- 不解析方法体指令链做 defineClass/Runtime.exec 模式识别（留待后续）
- 不反编译、不解密 payload（交给人工）
- 不改 clean 流程
- 不改其他 scanner

---

## 2. 架构

```
BytecodeTamperScanner（已有）
  检出 tamper 时新增：
  ├── ConstantPoolExtractor.utf8Constants(memBytes / diskBytes)   ← 新 helper 类
  │     解析常量池 CONSTANT_Utf8，两份做差集 → 新增字串
```

## 3. 提取与过滤逻辑

### 3.1 ConstantPoolExtractor

```java
public final class ConstantPoolExtractor {
    private ConstantPoolExtractor() {}

    /** 解析 class 字节码常量池里所有 CONSTANT_Utf8 字符串。异常返回空 set，不抛。 */
    public static java.util.Set<String> utf8Constants(byte[] classBytes) {
        java.util.Set<String> out = new java.util.LinkedHashSet<>();
        if (classBytes == null || classBytes.length < 10) return out;
        try (java.io.DataInputStream in =
                 new java.io.DataInputStream(new java.io.ByteArrayInputStream(classBytes))) {
            in.readInt();            // magic 0xCAFEBABE
            in.readUnsignedShort();  // minor
            in.readUnsignedShort();  // major
            int cpCount = in.readUnsignedShort();
            for (int i = 1; i < cpCount; i++) {
                int tag = in.readUnsignedByte();
                switch (tag) {
                    case 1:  out.add(in.readUTF()); break;                 // Utf8
                    case 7: case 8: case 16: case 19: case 20:             // Class/String/MethodType/Module/Package
                        in.readUnsignedShort(); break;
                    case 15: in.readUnsignedByte(); in.readUnsignedShort(); break; // MethodHandle
                    case 3: case 4: case 9: case 10: case 11: case 12: case 17: case 18:
                        in.readInt(); break;                                // Int/Float/Ref/NameAndType/Dynamic/InvokeDynamic
                    case 5: case 6: in.readLong(); i++; break;             // Long/Double take 2 slots
                    default: break;
                }
            }
        } catch (Throwable ignored) {
            // 损坏字节码 → 返回已收集部分（best effort）
        }
        return out;
    }
}
```

### 3.3 filterSuspicious 启发式

命中任一条件即保留为可疑：

```java
private List<String> filterSuspicious(Set<String> news) {
    List<String> out = new ArrayList<>();
    for (String s : news) {
        if (s == null || s.isEmpty()) continue;
        if (isPureDescriptor(s)) continue;        // 剔除 ()V / Ljava/...; / [I 等
        if (s.length() <= 4) continue;            // 剔除 <init>/get 等短名（路径/类名一般更长）
        boolean looksPath   = s.contains("/") || s.contains("*");
        boolean highEntropy = shannonEntropy(s) > 3.5;  // 疑似 Base64/随机类名
        boolean longToken   = s.length() > 8;
        if (looksPath || highEntropy || longToken) out.add(s);
    }
    return out;
}

// 纯字节码描述符：以 ( 开头(方法描述符)、L...; (对象类型)、[ (数组) 开头
private boolean isPureDescriptor(String s) {
    if (s.isEmpty()) return false;
    char c0 = s.charAt(0);
    if (c0 == '(' || c0 == '[') return true;
    if (c0 == 'L' && s.endsWith(";")) return true;
    return false;
}

// 香农熵，区分随机串 vs 普通单词
private double shannonEntropy(String s) {
    int[] freq = new int[256];
    for (int i = 0; i < s.length(); i++) { char ch = s.charAt(i); if (ch < 256) freq[ch]++; }
    double ent = 0.0; int len = s.length();
    for (int f : freq) if (f > 0) { double p = (double) f / len; ent -= p * (Math.log(p) / Math.log(2)); }
    return ent;
}
```

**说明**：`injectedStringsRaw` 永远保留全量，所以即使过滤误杀了某个真路径，应急人员仍可在 raw 里找到——过滤只是"先看可疑版快速定位"，不丢信息。

## 4. 字节码存证 dump

### 4.1 路径与实现

```java
private void dumpEvidence(String findingId, byte[] mem, byte[] disk,
                          String evidenceDir, Finding f) {
    if (evidenceDir == null || evidenceDir.isEmpty()) {
        f.attributes.put("evidenceDumped", false);
        return;
    }
    try {
        java.nio.file.Path dir = java.nio.file.Paths.get(evidenceDir, "evidence", findingId);
        java.nio.file.Files.createDirectories(dir);
        java.nio.file.Files.write(dir.resolve("tampered.class"), mem);
        java.nio.file.Files.write(dir.resolve("original.class"), disk);
        f.attributes.put("evidenceDumped", true);
    } catch (Throwable t) {
        f.attributes.put("evidenceDumped", false);
    }
}
```

### 4.2 evidenceDir 传递链

```
MemHunterAgent.agentmain
  args.options.get("evidence-dir")   // scan 时可能为 null
  → new AgentTypeScanner().scan(inst, report, evidenceDir)
    → new BytecodeTamperScanner().scan(inst, report, evidenceDir)
```

`AgentTypeScanner.scan` 和 `BytecodeTamperScanner.scan` 各增加一个 `String evidenceDir`
参数。TransformerScanner / DynamicClassScanner 不需要 evidenceDir，AgentTypeScanner
内部只把它传给 BytecodeTamperScanner。

### 4.3 容错

dump 失败（无 evidence-dir、IO 错误、权限）**不影响 finding 产出**——finding 照常带
injectedStrings/injectedStringsRaw，只是 `evidenceDumped=false`。

## 5. 测试 & 验收

### 5.1 单元测试

**ConstantPoolExtractorTest：**
- 解析 String.class 真实字节码 → 返回非空集合，含已知方法名（如 `toString`）
- 解析含 long/double 常量的类 → 槽位计数正确，后续常量不错位（用 `Long.class` 或自造含 long 常量的类）
- 解析 null / 长度 <10 / 损坏字节码 → 返回空集合不抛

**BytecodeTamperScannerTest（扩展现有 6 个测试）：**
- modified 比 original 多一个字符串常量 → `injectedStringsRaw` 含该字串
  （用两份手工字节码或读两个不同真实类）
- filterSuspicious：`/yyy` 保留、`()V` 剔除、`Ljava/lang/String;` 剔除、
  高熵随机串保留、`get` 剔除（≤4）
- evidenceDir=null → `evidenceDumped=false`，finding 仍带 injectedStrings
- evidenceDir=@TempDir → tampered.class + original.class 写出，字节内容与输入一致
