# v0.18 设计：哥斯拉依赖类降级

**日期**：2026-06-04
**前置版本**：v0.17（finding 同类去重/合并）
**背景**：v0.17 去重暴露出 critical 层混着「非内存马」的东西。实地（哥斯拉靶机，ground truth：
客户端 getAllFilter 只列 4 个 Filter 马）扫描得 critical 8——其中 4 个是真注册的 Filter 马
（`tomcat-filter`，有 path=[/*]），另外 4 个是 `class-servlet` 型的 `org.apache.coyote.*` 类
（`StackTraceElementDeserializer`、`AbstractTypeResolver`、`DOMDeserializer`、`NullsConstantProvider`），
**不在注入清单里**。

这 4 个是哥斯拉为让 Filter 马运行而一起注入的 **Jackson 依赖库类**——哥斯拉把整个 Jackson
打包进 payload、改包名伪装成 `org.apache.coyote.*` 一起 defineClass 进 JVM。它们确实是恶意注入的
类（该报），但**只是被加载的库代码、没注册成 Web 组件、不拦请求、无访问路径**，不是激活的内存马。

它们被 `masqueraded-package +5` 顶到 13-14 = critical，与真马（16）同级，使 critical 数虚高。

---

## 1. 目标 & 非目标

### 1.1 目标

让"伪装包名但仅被加载、未注册成组件"的依赖类从 critical 降到 high——critical 只留激活的真马。
依赖类仍报（high，不漏报）。

### 1.2 非目标

- 不改 scanner、不改去重、不碰 clean/verify、不改其它规则
- 不漏报依赖类（仍在 high）
- 不新增规则（改现有 MasqueradedPackageRule）

---

## 2. 核心认知与判据

| | 真·注册的 Filter 马 | 哥斯拉依赖类 |
|---|---|---|
| finding type | `tomcat-filter` / `spring-*`（容器注册视角） | `class-servlet` / `class-filter`（ClassScanner 全类视角）|
| 注册成组件 | 是（isDynamic=true、有 urlPatterns） | 否（仅被加载） |
| attributes | urlPatterns/mappings 等 | 空 |
| reasons 含 | runtime-only、url-pattern-wildcard | 无（仅 implements-web-component / code-source-null / masqueraded-package 等）|

**判据**：`class-*` 型 finding = ClassScanner 发现的"仅被加载的类"，没注册成组件。所以"伪装包名"的
恶意性对两者意义不同：**注册组件伪装 = 激活的内存马（该 critical）；仅加载的类伪装 = 马的依赖库
（该 high）**。判据用 finding.type 是否以 `class-` 开头，简洁且与上述特征直接对应；真马是
tomcat-/spring- 型，天然不受影响。

## 3. 改动（单处：MasqueradedPackageRule）

`MasqueradedPackageRule.evaluate` 增加一道门——伪装加分仅对**非 class-*** 型 finding 生效：

```java
@Override
public int evaluate(Finding finding, ScanContext ctx) {
    if (finding == null || finding.className == null || ctx == null || ctx.whitelist == null) return 0;
    if (!ctx.whitelist.isFrameworkPackage(finding.className)) return 0;
    if (finding.codeSource == null || finding.codeSource.isEmpty()) {
        // v0.18: the masquerade bonus only applies to registered components (tomcat-/spring-).
        // A class-* finding is a merely-loaded class, not an activated memshell — most likely a
        // dependency library the real shell pulled in (Godzilla ships Jackson renamed into
        // org.apache.coyote.* and defines those classes alongside the registered filter shells).
        // Such a class is still reported, but must not be elevated to critical.
        if (finding.type != null && finding.type.startsWith("class-")) return 0;
        return 5;
    }
    return 0;
}
```

仅新增中间那个 `if (finding.type ... startsWith("class-")) return 0;`，其余不变。

### 3.1 评分效果（真实数据验证）

- 真马 `tomcat-filter BuilderBasedDeserializer`：type=tomcat-filter → 仍 +5 → 16 = **critical**（不变）
- 依赖类 `class-servlet StackTraceElementDeserializer`：type=class-servlet → 不给 +5 →
  14-5 = **9 = high**

### 3.2 语义

「伪装加分只对被容器注册的组件生效——只有挂上去能拦请求的伪装类才是激活的内存马。仅被加载的
伪装类是马的依赖库，降到 high。」

## 4. 测试 & 验收

### 4.1 单元测试

**MasqueradedPackageRuleTest（扩展）：**
- 注：现有 `finding(className, codeSource)` helper 不设 type（默认 null），现有期望 +5 的用例
  type=null 非 class-*，本改动后仍 +5——**既有用例不回退**。
- 新增带 type 的 helper / 用例：
  - `class-filter` + 伪装包名 + null codeSource → **0**（不给 +5）
  - `class-servlet` + 伪装包名 + null codeSource → **0**
  - `tomcat-filter` + 伪装包名 + null codeSource → **5**（注册组件，不变）
  - `spring-mapping` + 伪装包名 + null codeSource → **5**（注册组件，不变）

**RuleEngineTest（集成）：**
- 构造哥斯拉依赖类式 finding（type=class-servlet, className=org.apache.coyote.deser.X,
  codeSource=null, attributes 空）走完整链 → level **不是 critical**（应为 high）
- 构造真注册马 finding（type=tomcat-filter, 同 className 前缀, codeSource=null,
  isDynamic=true, urlPatterns=[/*]）走完整链 → 仍 **critical**（v0.13 行为不回退）

### 4.2 验收（实地，哥斯拉 ground truth）

重启 Tomcat + 注入哥斯拉 → 复扫，验证：
- critical 只剩真注册的 Filter 马（数量与哥斯拉客户端 getAllFilter 列的一致，不含依赖类）
- 4 个 `class-*` 依赖类降到 high（仍报，不漏）
- JSP shell、哥斯拉 Servlet 马（className=null）不受影响
