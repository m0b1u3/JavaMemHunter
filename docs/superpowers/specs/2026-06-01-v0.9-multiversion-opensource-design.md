## 3. ServletApiBridge & 反射兼容

### 3.1 问题

现有 scanner / cleaner 多处 `Class.forName("javax.servlet.Filter")`、
`org.apache.catalina.core.StandardContext` 字段反射假设
`javax.servlet.Filter` 类型。SB3 上 javax 不存在，类加载即失败。

### 3.2 ServletApiBridge

新增 `agent/src/main/java/com/memhunter/agent/compat/ServletApiBridge.java`：

```java
public final class ServletApiBridge {
    public enum Flavor { JAVAX, JAKARTA }

    private static final Flavor FLAVOR = detect();
    private static final Class<?> FILTER_CLASS    = load("Filter");
    private static final Class<?> SERVLET_CLASS   = load("Servlet");
    private static final Class<?> LISTENER_CLASS  = load("ServletContextListener");

    public static Flavor flavor()         { return FLAVOR; }
    public static Class<?> filterClass()  { return FILTER_CLASS; }
    public static Class<?> servletClass() { return SERVLET_CLASS; }
    public static Class<?> listenerClass(){ return LISTENER_CLASS; }
    public static boolean isFilter(Object o)   { return FILTER_CLASS.isInstance(o); }
    public static boolean isServlet(Object o)  { return SERVLET_CLASS.isInstance(o); }
    public static boolean isListener(Object o) { return LISTENER_CLASS.isInstance(o); }

    private static Flavor detect() {
        try { Class.forName("jakarta.servlet.Filter"); return Flavor.JAKARTA; }
        catch (ClassNotFoundException e) { return Flavor.JAVAX; }
    }
    private static Class<?> load(String simple) {
        String pkg = FLAVOR == Flavor.JAKARTA ? "jakarta.servlet." : "javax.servlet.";
        try { return Class.forName(pkg + simple); }
        catch (ClassNotFoundException e) {
            throw new IllegalStateException("missing " + pkg + simple, e);
        }
    }

    private ServletApiBridge() {}
}
```

**调用点改造**（agent 模块）：

- `TomcatFilterScanner` / `TomcatServletScanner` / `TomcatListenerScanner` /
  `TomcatValveScanner`：删 `Class.forName("javax.servlet.X")`，改用
  `ServletApiBridge.filterClass()` 等。
- `TomcatFilterCleaner` / `TomcatServletCleaner` / `TomcatListenerCleaner`：
  反射读 `ApplicationFilterConfig.filter` / `context.filterConfigs` 等字段时
  不强 cast 到 `javax.servlet.Filter`，用 `Object` 持有并通过 bridge.isFilter()
  校验。
- `TomcatValveCleaner`：valve 不依赖 servlet API，无需改造。
- Spring scanner / cleaner：`org.springframework.web.servlet.HandlerInterceptor`
  在 Spring 5 / 6 包名相同；接口方法签名引用 `HttpServletRequest`
  (javax vs jakarta)，但反射调用不 cast，影响小。复核后无须改动。

**Tomcat 内部类对照**：`org.apache.catalina.core.ApplicationFilterConfig`、
`StandardContext`、`StandardWrapper`、`StandardContextValve`
在 Tomcat 9 与 10 类全限定名相同，字段名相同，仅依赖的 servlet API
包名换。所以 scanner 端只要不强 cast 到 javax/jakarta 类型即跨版本。

**Spring 内部类对照**：`AbstractHandlerMapping.adaptedInterceptors`、
`InterceptorRegistry` 在 Spring 5 与 6 类名 + 字段名相同。理论零改动。

### 3.3 单测

`ServletApiBridgeTest`：

- detect 在 javax-only classpath 返回 JAVAX
- detect 在 jakarta-only classpath 返回 JAKARTA
- filterClass / servletClass / listenerClass 与 flavor 对应
- isFilter / isServlet / isListener 判定对错样本

真实多版本验证落到 `integration-tests`。

## 4. integration-tests 模块

### 4.1 pom.xml 骨架

顶层 pom `<modules>` 加 `integration-tests`：

```xml
<artifactId>integration-tests</artifactId>
<packaging>jar</packaging>

<profiles>
  <profile>
    <id>sb27</id>
    <activation><activeByDefault>true</activeByDefault></activation>
    <properties>
      <spring-boot.version>2.7.18</spring-boot.version>
      <test-target.module>test-target</test-target.module>
      <test-target.injector.module>test-target-injector</test-target.injector.module>
    </properties>
  </profile>
  <profile>
    <id>sb32</id>
    <properties>
      <spring-boot.version>3.2.5</spring-boot.version>
      <test-target.module>test-target-sb32</test-target.module>
      <test-target.injector.module>test-target-injector-sb32</test-target.injector.module>
    </properties>
  </profile>
</profiles>
```

`maven-surefire-plugin` 用 `failsafe` 替代（IT 后缀），并通过
system property 传 test-target.jar 与 injector.jar 的路径。

### 4.2 目录布局

```
integration-tests/
└── src/test/java/com/memhunter/it/
    ├── ProfileFixture.java
    ├── E2eScanIT.java
    ├── E2eCleanIT.java
    └── E2eVerifyIT.java
```

### 4.3 ProfileFixture 责任

- `@BeforeAll`：根据 `-Dprofile=sb27/sb32`（或 Maven profile 透传的 property）
  启动对应 `test-target*.jar`（ProcessBuilder + JDK 17 fork）
- 等 `http://localhost:8080/health` 返回 200，超时 60 秒
- 调 6 个 inject endpoint，确认 6 finding 全部到位
- `@AfterAll`：kill 子进程，归档 evidence 至 `target/evidence/<profile>/`

### 4.4 测试规模

| 测试类 | 方法 | 断言 |
|---|---|---|
| E2eScanIT | scanFindsAll6Findings | scan 报告含 6 finding，level/score 与既往 evidence 一致 |
| E2eCleanIT | @ParameterizedTest cleanRemovesFinding(type) | cleanResult.success=true 且 verify stillPresent=false |
| E2eVerifyIT | verifyAfterCleanReportsAbsent | 二次 verify 仍报 absent |

### 4.5 CI 跑法

```
./mvnw -pl integration-tests -Psb27 verify
./mvnw -pl integration-tests -Psb32 verify
```

### 4.6 test-target-sb32 / test-target-injector-sb32

参照现有 `test-target` 复制：
- 同样 6 个 inject endpoint
- pom.xml 改 Spring Boot 3.2.5 + 显式依赖 jakarta.servlet
- 源码 javax → jakarta 包名替换
- JDK 17 编译目标

`test-target-injector-sb32` 同理。

## 5. CI Workflow

### 5.1 .github/workflows/test.yml

```yaml
name: Test
on:
  push: { branches: [master] }
  pull_request: { branches: [master] }

jobs:
  unit:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with: { distribution: temurin, java-version: 17 }
      - run: ./mvnw -B -ntp -DskipITs verify

  integration:
    runs-on: ubuntu-latest
    strategy:
      fail-fast: false
      matrix:
        profile: [sb27, sb32]
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with: { distribution: temurin, java-version: 17 }
      - run: ./mvnw -B -ntp -DskipITs install
      - run: ./mvnw -B -ntp -pl integration-tests -P${{ matrix.profile }} verify
      - if: failure()
        uses: actions/upload-artifact@v4
        with:
          name: evidence-${{ matrix.profile }}
          path: integration-tests/target/evidence/
```

### 5.2 .github/workflows/release.yml

```yaml
name: Release
on:
  push: { tags: ['v*'] }

jobs:
  release:
    runs-on: ubuntu-latest
    permissions: { contents: write }
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with: { distribution: temurin, java-version: 17 }
      - run: ./mvnw -B -ntp -DskipTests package
      - uses: softprops/action-gh-release@v2
        with:
          files: |
            agent/target/agent-*.jar
            attach/target/attach-*.jar
          generate_release_notes: true
```

**JDK 选择说明**：CI 全用 JDK 17（Linux runner 无 Windows NIO Selector
bug，Tomcat embed 9/10 都能跑）。Windows + JDK 17 bug 在 README Known
Limitations 章节披露。

### 5.3 Issue / PR 模板

- `.github/ISSUE_TEMPLATE/bug_report.yml`：环境（JDK 版本 / Spring Boot 版本 / OS）
  / 复现步骤 / 期望 / 实际 / 附 evidence 文件
- `.github/ISSUE_TEMPLATE/feature_request.yml`：场景 / 提议 / 备选方案
- `.github/PULL_REQUEST_TEMPLATE.md`：变更摘要 / 关联 issue / 测试方式 /

### 6.3 历史 tag 补打

```
v0.1   ← merge commit of feature/v0.1-...
v0.2   ← feature/v0.2-container-scanning merge
v0.3   ← feature/v0.3-scoring-rules merge
v0.4   ← feature/v0.4-bytecode-baseline merge
v0.5   ← feature/v0.5-baseline merge
v0.6   ← feature/v0.6-tomcat-filter-clean merge
v0.6.1 ← feature/v0.6.1-clean-audit-fixes merge
v0.7   ← feature/v0.7-tomcat-cleaners-extension merge
v0.7.1 ← feature/v0.7.1-e2e-evidence merge
v0.8   ← feature/v0.8-spring-cleaners merge
v0.8.1 ← feature/v0.8.1-spring-clean-evidence merge
v0.8.2 ← feature/v0.8.2-audit-chain-fixes merge
v0.9   ← v0.9 merge commit
```

每个 tag 使用 `git tag -a vX.Y[.Z] <sha> -m "<release notes>"`，
最后 `git push origin --tags`。

**release.yml 对历史 tag 不友好**（要重 build 老代码）。解决：**历史 tag 仅打**，
GitHub Release 通过 `gh release create vX.Y --notes-from-tag` 手工建为
source-only release；release.yml 自动上传 jar 仅对 **v0.9 起** 的 release 生效。
若 release.yml 被历史 tag push 触发，允许 build 失败，不阻塞流程。

## 8. 验收标准 (DoD) & 风险

### 8.1 验收标准

1. `./mvnw -DskipITs verify` 全绿（沿用现有 233 单测 + 新增 ServletApiBridge 单测）
2. `./mvnw -pl integration-tests -Psb27 verify` 全绿（6 finding × scan/clean/verify）
3. `./mvnw -pl integration-tests -Psb32 verify` 全绿
4. `.github/workflows/test.yml` 在 GitHub 上跑过一次绿
5. `git tag -l` 输出 12 个历史 tag + `v0.9`，全部 push 到 origin
6. GitHub Releases 页 12 个历史 release（source-only）+ v0.9 release（含 agent.jar + attach.jar）
7. LICENSE / CONTRIBUTING.md / .github/ISSUE_TEMPLATE 在 master
8. README.md（英文）/ README.zh-CN.md（中文）双语就位
9. `java_memshell_scanner_design.md` §25 加 v0.9 条目
10. 本设计文档 commit
11. v0.9 feature 分支 push 到 origin（沿用 v0.8.1+ 模式）+ master merge

### 8.2 风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| SB3.2 上 Tomcat 10 内部类字段名/类型与 Tomcat 9 不同 | 中 | 高 | 优先 §3 反射适配 + integration-tests sb32 立刻跑，bug 早暴露 |
| Spring 6 AbstractHandlerMapping.adaptedInterceptors 字段类型变了 | 低 | 中 | 同上 |
| integration-tests 在 CI Linux runner 上 attach self 受限 | 中 | 中 | ProcessBuilder fork 独立子进程，已在设计内 |
| 13 个历史 tag 打错 commit | 低 | 低 | 打 tag 前 `git log --oneline --merges` 列出所有 merge 逐一对照 |
| JDK 8 / 11 / 21 在 CI 未跑 | 中 | 中 | 列入 Known Limitations，v0.9.1 加 JDK matrix |
| README 英文版本支持矩阵承诺超出实测范围 | 低 | 中 | "verified" 仅列 CI 实际跑过组合 |
| release.yml 被历史 tag 触发构建老代码失败 | 中 | 低 | 容忍失败；历史 release 通过 `gh release create` 手工 source-only 建 |
