# v0.16 设计：JSP webshell 访问路径反推

**日期**：2026-06-04
**前置版本**：v0.15（摘要逐条标注访问路径/定位信息）
**背景**：v0.15 给摘要每条加了路径，但 JSP webshell（`org.apache.jsp.*_jsp`，type=`class-servlet`）
没显示路径——因为它经 ClassScanner（扫所有已加载类）发现，attributes 里没有 mappings/urlPatterns
字段。实地扫到的 `org.apache.jsp.wwwwxxx_jsp`、`org.apache.jsp.shell_jsp` 都是 `path` 空白。

JSP webshell 是**文件型 webshell**（磁盘上有 `.jsp` 文件，Tomcat 编译成 `org.apache.jsp.*_jsp` 类），
不是内存马。其访问路径编码在类名里，可纯字符串反推——而访问路径正是应急封堵/定位文件最需要的。

---

## 1. 目标 & 非目标

### 1.1 目标

ClassScanner 发现 `org.apache.jsp.*_jsp` 类时，从类名反推 `.jsp` 访问 URL，存进 finding，使
v0.15 摘要能显示 `path=[/wwwwxxx.jsp]`。

### 1.2 非目标

- 不拼磁盘绝对路径（webapp docBase 要额外查、不一定准；`.jsp` URL 已足够定位+删除）
- 不处理 Tomcat 全套转义规则（`_002d`→`-` 等），转义字符原样保留、不报错（webshell 罕用特殊字符）
- 不改其它 scanner、不碰 clean/verify、不改评分

---

## 2. 架构

agent 端反推存 attributes + attach 端 printer 显示（复用 v0.15 的 appendLocation 机制）。

### 2.1 新增 `JspPathResolver`（agent 端，纯函数）

`agent/.../scanner/JspPathResolver.java`：
```java
public final class JspPathResolver {
    private JspPathResolver() {}
    private static final String PREFIX = "org.apache.jsp.";

    /**
     * Reverse-maps a compiled JSP class name to its .jsp access URL.
     * Returns null when the class name is not a Tomcat-compiled JSP.
     * Examples:
     *   org.apache.jsp.wwwwxxx_jsp     -> /wwwwxxx.jsp
     *   org.apache.jsp.admin.x_jsp     -> /admin/x.jsp
     * Escaped chars (_002d etc.) are left as-is (not un-escaped).
     */
    public static String toJspUrl(String className) {
        if (className == null || !className.startsWith(PREFIX)) return null;
        String rest = className.substring(PREFIX.length());       // wwwwxxx_jsp / admin.x_jsp
        if (rest.isEmpty()) return null;
        if (!rest.endsWith("_jsp")) return null;
        String withoutSuffix = rest.substring(0, rest.length() - "_jsp".length()); // wwwwxxx / admin.x
        if (withoutSuffix.isEmpty()) return null;
        String path = withoutSuffix.replace('.', '/');            // wwwwxxx / admin/x
        return "/" + path + ".jsp";                               // /wwwwxxx.jsp / /admin/x.jsp
    }
}
```

### 2.2 ClassScanner 调用

`ClassScanner.scan()` 构造 finding 后，新增：
```java
String jspUrl = JspPathResolver.toJspUrl(f.className);
if (jspUrl != null) f.attributes.put("jspPath", jspUrl);
```
非 JSP 类 → jspUrl null → 不存。其它字段（type/name/className/codeSource/classLoader/id）不变。

### 2.3 ScanSummaryPrinter 显示（attach 端，扩展 v0.15 appendLocation）

在 `appendLocation` 中，对 `class-servlet` / `class-filter` 类型新增分支：若 attributes 含 `jspPath`，
显示 `path=[<jspPath>]`。无 jspPath → 维持现状（不加段）。

```java
} else if (type != null && type.startsWith("class-")) {
    JsonNode jp = attrs.path("jspPath");
    if (!jp.isMissingNode() && !jp.isNull() && !jp.asText("").isEmpty()) {
        line.append("  path=[").append(jp.asText()).append("]");
    }
}
```
放在 appendLocation 现有 if-else 链末尾（在 dynamic-class 等无字段类型之前的合适位置；class-* 是
独立前缀，与现有 tomcat-/spring-/agent- 分支不冲突）。

## 4. 测试 & 验收

### 4.1 单元测试

**JspPathResolverTest：**
- `org.apache.jsp.wwwwxxx_jsp` → `/wwwwxxx.jsp`
- `org.apache.jsp.shell_jsp` → `/shell.jsp`
- 带子目录 `org.apache.jsp.admin.x_jsp` → `/admin/x.jsp`
- 非 JSP 类 `com.example.Foo` → null
- 不以 `_jsp` 结尾 `org.apache.jsp.weird` → null
- 仅前缀 `org.apache.jsp.` → null
- null → null

**ClassScanner：不新增单测。** 理由：ClassScanner 依赖真实 `Instrumentation.getAllLoadedClasses()`
且按接口判定 web 组件，单测需 mock Instrumentation 并提供一个类名为 `org.apache.jsp.x_jsp` 又实现
Servlet 接口的合成类，成本高。而 ClassScanner 的改动只是 2 行接线（调 `JspPathResolver.toJspUrl`
存 jspPath），核心反推逻辑全在 `JspPathResolver` 纯函数里、由 JspPathResolverTest 充分覆盖；显示由
ScanSummaryPrinterTest 覆盖。接线正确性由 §4.2 实地验收保证（实地确有 `org.apache.jsp.*_jsp` 类）。

**ScanSummaryPrinterTest：**
- `class-servlet` finding + attributes.jspPath=`/wwwwxxx.jsp` → 行含 `path=[/wwwwxxx.jsp]`
- `class-servlet` finding 无 jspPath → 行不含 `path=`
- 既有 v0.15 测试仍通过

### 4.2 验收（实地）

对哥斯拉靶机 scan（含 JSP shell），验证摘要：
- `org.apache.jsp.wwwwxxx_jsp` 行显示 `path=[/wwwwxxx.jsp]`
- `org.apache.jsp.shell_jsp` 行显示 `path=[/shell.jsp]`
- 哥斯拉内存马（tomcat-filter/servlet）的 path 显示不回退（v0.15 行为保留）

## 5. 参考

- ClassScanner（`agent/.../scanner/ClassScanner.java`）：扫所有已加载类，对 web 组件类生成
  `class-<type>` finding，存 type/name/className/codeSource/classLoader/id
- v0.15 ScanSummaryPrinter.appendLocation（attach 端按 type 取路径字段追加 `path=`/`trigger=` 等）
- Tomcat JSP 编译命名：`<webapp根的.jsp路径>` → `org.apache.jsp.<目录>.<文件名>_jsp`
- JSP webshell vs 内存马区别：JSP 是文件型（磁盘有 .jsp、codeSource 指向 /work/Catalina/ 编译目录、
  重启仍在、删文件即清）；内存马无磁盘文件、codeSource=null、重启即清
