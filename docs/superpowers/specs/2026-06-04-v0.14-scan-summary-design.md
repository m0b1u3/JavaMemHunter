# v0.14 设计：attach 端扫描摘要 + 默认输出路径

**日期**：2026-06-04
**前置版本**：v0.13（伪装框架包检测）
**背景**：当前 scan 跑完，用户的 attach 终端只打印 `agent loaded successfully into PID <pid>`，
所有结果都在 `--output` 指定的 JSON 文件里——用户看不到结果，得自己打开 JSON 翻。而且 agent
的 `scan finished, findings=N` 那行打在目标 Tomcat 的 stdout（另一个进程），attach 终端根本看不到。
此外，不带 `--output` 时 agent 把 JSON 写到目标 JVM 的 tmpdir，路径用户/attach 端都不易知道。

---

## 1. 目标 & 非目标

### 1.1 目标

1. scan 完成后，在用户的 **attach 终端**直接打印精简摘要：summary 计数 + 逐条
   critical/high/suspicious（四字段一行），low 只计数不逐条。
2. **无论加不加 `--output` 都能看到摘要、报告都可靠落地**：不带 `--output` 时 attach 端
   默认把报告写到 **attach 进程当前目录**的 `memhunter-scan-<时间戳>.json`（绝对路径）。
3. 末尾打印报告全路径，方便取证、拿 finding id 去 clean。

### 1.2 非目标

- 不改 agent 扫描逻辑、不改 JSON 报告内容（仍全量含 low，取证用）
- 不碰 clean / verify 流程
- 摘要不显示 finding id（要 id 去 JSON 拿；critical/high 就十几条）

---

## 2. 架构

纯 attach 端改动，复用 attach 已有的 Jackson（`AttachMain` 读 VerifyResult 已用
`com.fasterxml.jackson.databind.ObjectMapper`，依赖经 memhunter-agent 传递）。

### 2.1 默认输出路径注入（AttachMain）

`AttachMain.run` 拼 `agentArgs` 时，针对 **scan 命令**：若用户 options 里**没有 `--output`**，
attach 端生成默认绝对路径并追加到 agentArgs：
```
<attach进程CWD绝对路径>/memhunter-scan-<时间戳>.json
```
若用户**传了 `--output`**，把它解析成绝对路径（`new File(userValue).getAbsolutePath()`）后透传，
保证 agent（跨进程）与 attach 端读写同一文件。

只对 scan 命令做此注入，clean/verify 不动。

### 2.2 摘要打印（新类 ScanSummaryPrinter）

agent 跑完、`agent loaded successfully` 打印之后，scan 命令分支调用
`ScanSummaryPrinter.print(out, reportPath)`：

1. 读 `reportPath` 的 JSON（ObjectMapper → JsonNode 或轻量 POJO）。
2. 打印：
   ```
   [memhunter] scan summary (PID <pid>):
     critical: 11  high: 4  suspicious: 0  low: 141
     [critical] tomcat-filter  org.apache.coyote.ser.SerializerCache  score=16
     [critical] tomcat-filter  org.apache.coyote.util.StdDateFormat   score=16
     ... (逐条 critical → high → suspicious，每条四字段一行)
   [memhunter] full report: E:\learn\JavaMemHunter\memhunter-scan-<ts>.json
   ```
   - 计数行从 JSON `summary.critical/high/suspicious/low` 取。
   - 逐条只列 level ∈ {critical, high, suspicious}，按该顺序分组；每条格式
     `  [<level>] <type>  <className>  score=<score>`（className 为 null 时打印 `<null>`）。
   - low 不逐条。
   - 末行打印报告绝对路径。

3. **容错**：读/解析失败不抛、不让命令失败——降级打印
   `[memhunter] scan finished, report at <path> (summary unavailable: <原因>)`。

### 2.3 文件

- 新增：`attach/src/main/java/com/memhunter/attach/ScanSummaryPrinter.java`
  （`static void print(PrintStream out, String reportPath)`，单一职责：读 JSON → 格式化 → 打印）
- 新增：`attach/src/test/java/com/memhunter/attach/ScanSummaryPrinterTest.java`
- 修改：`attach/src/main/java/com/memhunter/attach/AttachMain.java`
  （scan 命令：默认 output 注入 + 调 ScanSummaryPrinter）
- 修改：`attach/src/test/java/com/memhunter/attach/AttachMainTest.java`
  （默认路径注入测试）

### 2.4 reportPath 的确定

AttachMain 在拼 agentArgs 时已经知道最终的 output 路径（用户给的或默认生成的），把这个绝对路径
传给 `ScanSummaryPrinter.print`。`AttachExecutor.explicitOutputPath(agentArgs)` 也能从 agentArgs
解析出来——优先让 AttachMain 直接持有该路径变量传下去，不重复解析。

## 3. 数据来源（scan.json 字段，已确认）

- `summary.critical` / `.high` / `.suspicious` / `.low`：int 计数
- `findings[]`：每条含 `level`(String)、`type`(String)、`className`(String, 可能 null)、
  `score`(int)、`name`、`id` 等
- `target.pid`：用于摘要标题（也可由 AttachMain 直接持有的 pid 传入，避免依赖 JSON）

PID 来源：AttachMain 已有 `pid` 变量，直接传给 printer 作标题，不依赖 JSON 的 target.pid。

## 4. 测试 & 验收

### 4.1 单元测试

**ScanSummaryPrinterTest：**
- 给一个含 critical×2 / high×1 / suspicious×1 / low×3 的临时 JSON 文件（@TempDir 写出）→
  捕获 PrintStream → 断言：含计数行（critical: 2 ... low: 3）、含 2 条 critical + 1 high + 1
  suspicious 的逐条行、**不含** low 的逐条 className、含报告路径行。
- className 为 null 的 finding → 输出 `<null>` 不抛 NPE。
- reportPath 指向不存在文件 / 损坏 JSON → 打印降级行、不抛异常。

**AttachMainTest（扩展）：**
- scan 命令不带 --output → 拼出的 agentArgs 含 `--output` 且值是绝对路径、以
  `memhunter-scan-` 开头、`.json` 结尾。
- scan 命令带 `--output relative.json` → agentArgs 里该值被转为绝对路径。
- clean / verify 命令 → 不注入默认 --output（保持原样）。

（AttachMain 默认路径注入逻辑应抽成可单测的静态方法，如
`String resolveScanOutput(Map<String,String> options, String cwd)`，便于在不真正 attach 的
情况下断言。）

### 4.2 验收（实地）

对当前哥斯拉靶机 scan（PID 用 jps 查），**不带 --output**：
- attach 终端直接打印摘要：critical 11 / high 4 / suspicious 0 / low 141 + 逐条高危行
- 当前目录生成 `memhunter-scan-<ts>.json`
- 末行打印该报告绝对路径

再带 `--output scan.json` 跑一次：摘要照常打印，报告写到指定文件。
