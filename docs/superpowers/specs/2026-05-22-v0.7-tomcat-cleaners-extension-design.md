## 1. 目标与范围

### 1.1 目标

把 v0.6 Tomcat Filter 清理能力扩展到 Servlet / Listener / Valve 三类内存马，沿用 v0.6 的 5-Phase 模板（A 复扫 / B 备份 / C 原子副本替换 / D 销毁 / E verify 复扫）+ v0.6.1 的审计闸门（PlanReconciler + EXIT_PLAN_STALE + Phase D 三标签）。

**3 类新 Cleaner：**

1. **TomcatServletCleaner** — 清理 `tomcat-servlet`（Wrapper / servletMappings / children）
2. **TomcatListenerCleaner** — 清理 `tomcat-listener-{request|session|context|other}`（applicationEventListeners / applicationLifecycleListeners 等数组字段）
3. **TomcatValveCleaner** — 清理 `tomcat-valve`（Pipeline 链表）

**架构层目标：**

4. **CleanPlan 字段抽象**：`filterName/filterClass/urlPatterns` → `targetName/targetClass + details: Map<String,Object>`。每个 cleaner 把类型专属信息塞入 `details`。
5. **CleanerRegistry**：type → `Function<Object, Cleaner>` 查表。MemHunterAgent dispatch 走 polymorphic 路径，不再硬编码 `TomcatFilterCleaner`。
6. **PlanReconciler 字段重命名**：`filterClass` 比对 → `targetClass`，行为不变。
7. **RollbackManager → strategy-per-cleaner**：每个 cleaner 自带 rollback。原 `RollbackManager` 拆为 `FilterRollbackStrategy` + `RollbackStrategy` 接口。
8. **AbstractTomcatCleaner**：模板基类，共享 Phase A 复扫、Phase D 三标签销毁、Phase E 复扫+自动 rollback；子类填充 Phase B/C。

### 1.2 非目标

- **不**改 scanner（4 个 scanner 已稳定 v0.5）。
- **不**做 Spring Mapping / Interceptor 清理（v0.8+）。
- **不**改 evidence 目录布局（仍 `<base>/evidence/<findingId>/clean-plan.json`）。
- **不**提供 batch clean。
- **不**试图兼容 v0.6 老 evidence JSON 的 `filterName/filterClass/urlPatterns` 字段。schema 不一致由 PlanReconciler 自然拒绝，操作员重跑 dry-run 即可——审计链一致性更重要。
- **不**重构 RuleEngine / scoring。

## 2. 组件改动

### 2.1 新增

#### 2.1.1 CleanerRegistry

`agent/.../cleaner/CleanerRegistry.java`：

```java
public final class CleanerRegistry {
    private final Map<String, Function<Object, Cleaner>> byEquals = new LinkedHashMap<>();
    private final Map<String, Function<Object, Cleaner>> byPrefix = new LinkedHashMap<>();

    public CleanerRegistry register(String typeOrPrefix, boolean prefix,
                                    Function<Object, Cleaner> factory) {
        (prefix ? byPrefix : byEquals).put(typeOrPrefix, factory);
        return this;
    }

    public Cleaner resolve(String findingType, Object standardContext) {
        if (findingType == null) return null;
        Function<Object, Cleaner> f = byEquals.get(findingType);
        if (f != null) return f.apply(standardContext);
        for (Map.Entry<String, Function<Object, Cleaner>> e : byPrefix.entrySet()) {
            if (findingType.startsWith(e.getKey())) return e.getValue().apply(standardContext);
        }
        return null;
    }

    public static CleanerRegistry defaultRegistry() {
        return new CleanerRegistry()
            .register("tomcat-filter",   false, TomcatFilterCleaner::new)
            .register("tomcat-servlet",  false, TomcatServletCleaner::new)
            .register("tomcat-listener-", true, TomcatListenerCleaner::new)
            .register("tomcat-valve",    false, TomcatValveCleaner::new);
    }
}
```

#### 2.1.3 AbstractTomcatCleaner

`agent/.../cleaner/AbstractTomcatCleaner.java`：

```java
abstract class AbstractTomcatCleaner implements Cleaner {
    protected final Object standardContext;
    protected RollbackStrategy rollback;        // Phase B 末尾赋值
    protected String currentTargetName;
    protected String currentTargetClass;

    AbstractTomcatCleaner(Object standardContext) {
        this.standardContext = standardContext;
    }

    // 子类必须实现
    protected abstract String findingType();                 // "tomcat-servlet" 等；prefix 类型返回基准
    protected abstract boolean supportsType(String type);
    protected abstract Finding locateOnRescan(String findingId);
    protected abstract Map<String, Object> buildDetails(Finding finding);
    protected abstract void doPhaseB(Finding finding);       // 备份 + 赋值 rollback
    protected abstract void doPhaseC() throws CleanExecutionException;
    protected abstract String doPhaseD();                    // 返回 step label
    protected abstract boolean stillPresentOnRescan(String findingId);

    // 共享：plan(), execute(), 三标签 D, Phase E rollback 决策
    public final CleanPlan plan(Finding finding, boolean forced) { /* ... */ }
    public final CleanResult execute(CleanPlan plan, boolean forced) { /* ... */ }

    protected final String releaseTargetByConvention(Object target, String... methodNames) {
        if (target == null) return "phase-D: no-release-method";
        for (String name : methodNames) {
            try {
                java.lang.reflect.Method m = target.getClass().getMethod(name);
                m.invoke(target);
                return "phase-D: destroy-ran";
            } catch (NoSuchMethodException nse) {
                // try next
            } catch (java.lang.reflect.InvocationTargetException ite) {
                Throwable cause = ite.getCause() != null ? ite.getCause() : ite;
                return phaseDThrew(cause);
            } catch (Throwable t) {
                return phaseDThrew(t);
            }
        }
        return "phase-D: no-release-method";
    }

    private static String phaseDThrew(Throwable t) {
        String msg = t.getMessage() == null ? "" : t.getMessage();
        return "phase-D: destroy-threw: " + t.getClass().getSimpleName() + ": " + msg;
    }
}
```

## 3. 数据流

### 3.1 多类型 dispatch（confirm 阶段）

```text
用户：clean --id <fid> --confirm [--force]
         │
         ▼
AttachMain → loadAgent(...)
         │
         ▼
MemHunterAgent.dispatchCleanConfirm(ctx, args):
         │
         ▼
  ┌──────────────────────────────────────────────────────────┐
  │ 1. persisted = CleanPlanReader.read(planFile)           │
  │ 2. finding = findFindingById(ctx, id)                    │
  │    ├─ 跑 4 个 scanner（Filter/Servlet/Listener/Valve）   │
  │    ├─ 合并 + dedupById                                   │
  │    └─ 返回 null 则失败                                    │
  │ 3. cleaner = CLEANER_REGISTRY.resolve(finding.type, ctx)│
  │    ├─ "tomcat-filter"      → TomcatFilterCleaner         │
  │    ├─ "tomcat-servlet"     → TomcatServletCleaner        │
  │    ├─ "tomcat-listener-*"  → TomcatListenerCleaner       │
  │    ├─ "tomcat-valve"       → TomcatValveCleaner          │
  │    └─ 未匹配 → 落盘 failure，EXIT_EXECUTE_FAILED         │
  │ 4. fresh = cleaner.plan(finding, confirmForceFlag)       │
  │ 5. PlanReconciler.requireConsistent(...)                 │
  │    └─ stale → EXIT_PLAN_STALE                            │
  │ 6. result = cleaner.execute(fresh, confirmForceFlag)     │
  │ 7. EvidenceWriter.writeResult(id, result)               │
  └──────────────────────────────────────────────────────────┘
```

### 3.2 PlanReconciler 字段对照（v0.7）

| Persisted | Fresh | Confirm flag | 决策 |
|---|---|---|---|
| findingId | findingId | — | 严格相等 |
| **targetClass** | **targetClass** | — | 严格相等（替代 v0.6 filterClass） |
| score | score | — | 严格相等 |
| forced | forced | confirmForceFlag | 三方相等 |

`type`、`details`、`targetName` **不**进入 PlanReconciler 比对（与 v0.6 一致：reconciler 只看 4 个安全闸门字段）。

### 3.3 每类 Cleaner 的 Phase B/C 反射目标

```text
TomcatFilterCleaner（v0.6 已实现，仅适配 schema）:
  Phase B 备份 :  filterDefs[name] / filterMaps[name] / filterConfigs[name]
  Phase C 替换 :  filterConfigs → filterMaps.array → filterDefs（原子）

TomcatServletCleaner:
  Phase B 备份 :  StandardContext.findChild(name)（Wrapper 引用）
                 + Wrapper.findMappings() 副本
                 + servletMappings Map 副本
  Phase C 替换 :  原子副本（与 Listener/Valve 同款）
                 顺序：servletMappings (HashMap<String,String> 移除指向 name 的条目)
                       → children Map (HashMap remove name)

TomcatListenerCleaner:
  Phase B 备份 :  applicationEventListeners[] + applicationLifecycleListeners[]
                 中匹配 listener 引用的 index
  Phase C 替换 :  System.arraycopy 构造新 Object[]（去掉目标）
                 → 反射 set 回 context 字段
                 顺序：applicationEventListeners → applicationLifecycleListeners

TomcatValveCleaner:
  Phase B 备份 :  Pipeline 上 prev valve / target valve / next valve 三引用
                 + 完整 valve 链顺序快照（rollback 用）
  Phase C 替换 :  prev.setNext(next)（链表节点摘除）
                 若 target == pipeline.first → 反射改 pipeline.first = next
```

### 3.4 Phase D 销毁约定

| Cleaner | 销毁方法序列（依次试） |
|---|---|
| Filter | `release` |
| Servlet | `unload`, `destroy` |
| Listener | （空数组 → 直接 no-release-method） |
| Valve | `stop` |

抽象到 `AbstractTomcatCleaner.releaseTargetByConvention(Object, String...)`。

### 3.5 Finding 跨 scanner 查找

```java
private static Finding findFindingById(Object ctx, String id) {
    ScanReport report = new ScanReport();
    List<Finding> all = new ArrayList<>();
    all.addAll(new TomcatFilterScanner(ctx).scan(report));
    all.addAll(new TomcatServletScanner(ctx).scan(report));
    all.addAll(new TomcatListenerScanner(ctx).scan(report));
    all.addAll(new TomcatValveScanner(ctx).scan(report));
    for (Finding f : all) {
        if (id.equals(f.id)) return f;
    }
    return null;
}
```

不同 scanner 不会产生同 id（FindingIdGenerator 输入含 type）。

## 4. 错误处理

### 4.1 Type → Cleaner 解析失败

```java
Cleaner cleaner = CLEANER_REGISTRY.resolve(finding.type, ctx);
if (cleaner == null) {
    CleanResult result = new CleanResult();
    result.findingId = id;
    result.success = false;
    result.failureReason = "no cleaner registered for type: " + finding.type;
    result.executedSteps = Arrays.asList("pre-execute: unsupported finding type");
    result.executedAt = System.currentTimeMillis();
    new EvidenceWriter(evidenceDir).writeResult(id, result);
    return EXIT_EXECUTE_FAILED;
}
```

后续 v0.8 加 Spring cleaner 时，未注册的 type 仍走这个友好分支，不抛 NPE。

### 4.2 Phase C 失败 + Rollback 分层

每个 Cleaner 自带 `RollbackStrategy`：

| Cleaner | Rollback 顺序（反 Phase C） |
|---|---|
| Filter | filterDefs → filterMaps → filterConfigs |
| Servlet | children Map put back → servletMappings put back |
| Listener | applicationLifecycleListeners → applicationEventListeners |
| Valve | pipeline.first 复原 → prev.setNext(target) 复原 |

每个 strategy 抛 `RollbackFailedException`（共用 v0.6 异常）。catch 链与 v0.6 一致：
- `CleanExecutionException` → `success=false, rolledBack=true`
- `RollbackFailedException` → `success=false, rolledBack=false, failureReason="ROLLBACK FAILED: ..."`

### 4.3 Phase D 异常处理

沿用 v0.6.1 三标签机制（`destroy-ran / no-release-method / destroy-threw: <Class>: <msg>`）。抛异常永不触发 rollback（设计 §5 既定原则）。

Servlet Phase D 调两次 `releaseTargetByConvention`（unload + destroy）—— 拼接两个 step label。

### 4.4 Phase E 复扫失败

每个 cleaner 跑自己对应的 scanner。仍命中 → 自动 rollback（与 v0.6 一致）。

### 4.5 Tomcat 版本兼容失败

| 失败 | 处理 |
|---|---|
| Listener 数组字段在某 Tomcat 版本叫别名 | `ReflectUtil.tryReadField` 返回 Optional.empty → Phase B 失败，CleanResult.failureReason 写明字段缺失，建议重启 |
| Valve 链中 target 不存在 | Phase A 复扫已捕获 |
| Servlet `servletMappings` 字段在 Tomcat 10 改名 | 同 Listener 处理 |

## 8. 风险与限制

| 风险 | 缓解 |
|---|---|
| Servlet `servletMappings` 字段 Tomcat 7/8/9/10 命名差异 | ReflectUtil.tryReadAnyOf 多名 fallback；失败友好提示 |
| Listener 4 个数组字段在某些 Tomcat 版本只暴露 2 个 | Phase B 按字段存在性逐个备份；缺失字段跳过即可 |
| Valve target == pipeline.first 的边界 | 显式分支：先改 pipeline.first，再 setNext |
| Servlet 清理后 ApplicationContext.getServletRegistration 仍可能缓存 | Phase E 复扫只用 Scanner 验证；缓存层不在 v0.7 责任 |
| 老 v0.6 evidence 文件 confirm 时 PlanReconciler 抛错信息含混 | 显式测试 `confirmRejectsLegacyV06Plan` 验证错误消息提到 "targetClass mismatch (persisted=null, fresh=...)" |
| AbstractTomcatCleaner 抽象过度 / Filter 改造时引入回归 | TDD 先跑 Filter 既有测试再重构（Task 4） |
| Pipeline `getFirst` 返回 BasicValve 而非可清理对象 | TomcatValveScanner 已遍历，复用其遍历逻辑 |
